2.27.0 · 使用 DSH Pet 动画桌宠

主桌面、工作区和设置预览统一使用 dsh-pet 的透明 WebM 动画。默认内置蓝发小女仆，共114段动画，素材约57.8 MB。动画会显示待机小动作、点击回应、拖拽悬空、睡眠、醒来与转向，并结合对话中的思考、说话和情绪切换。

  1. 双击 WoWCompanion-2.27.1-windows-x64-setup.exe，按向导选择安装目录。安装完成后，从桌面或开始菜单打开“魔兽陪伴精灵”。
  2. 右键点击宠物，可打开聊天、切换随机动作、让宠物睡觉或醒来，以及翻转朝向。左键点按可触发回应，按住拖动可移动窗口。
  3. 打开设置 → 桌宠形象，选择内置宠物或导入动画包。形象、当前动作和50%～200%尺寸会同步到已打开的显示窗口。
  4. 继续使用原有聊天、语音字幕、记忆和魔兽世界连接。旧模型资料保存在个人档案中。新形象通过动画包管理，原模型文件需要另行准备为透明 WebM 动画素材。

导入自己的动画包

选择包含规范 pack.json 与所列 .webm 文件的目录。清单提供名称、资源列表和待机、点击、随机动作等动画池；睡眠可配置同套的开始、循环与醒来三段。先在设置中查看导入包的预览，再切换使用。

每包最多256个媒体文件，每个文件不超过32 MiB，总量不超过512 MiB。软件校验清单与路径，将允许的动画复制到个人资料目录的 dsh-pet-packs，供重启后继续读取。导入完成后，可在设置中选择该宠物、点播动作和调节尺寸。

动画素材与播放机制来自 dsh-pet，MIT 许可证，版权归属 PC2005-cloud。完整许可随内置动画包提供。旧版本的使用记录保存在下方，当前形象操作以本节为准。

2.26.0 · 安装与 Token 用量统计

桌面程序为 2.26.0；配套正式服插件与桥接仍为 2.25.0，无限服插件仍为 1.21.0。本轮新增可选统计和独立服务器数据中台，保留下面的 2.25.0 精简功能。

首次运行与日常设置

  1. 首次启动或升级后，先阅读统计告知。开关默认开启，点击“继续”后才开始收集。可关闭开关或选择“关闭统计”；选择“稍后”或按 Escape 不会开启。
  2. 打开设置 → 安装与用量统计，填入管理员提供的 HTTPS 服务根地址，例如 https://stats.example.com。不填写管理员密钥、模型 API Key 或游戏账号。
  3. 地址留空时不会联网发送。启用且地址有效后，在登记或恢复连接时发送检查点，运行期间固定每 300 秒（5分钟）上报累计计数；本页可查看本地用量、覆盖情况、最后成功时间和错误。
  4. 在同一设置页关闭“收集与上报”后保存即可停止；之前已发送的汇总仍保留在服务器。离线期间已启用的统计保留在本地，恢复联网后补报。

统计哪些内容

发送随机安装标识、版本、平台和累计用量计数。不发送聊天、角色资料、截图、音频、服务商名、模型名或 API Key。客户端自动生成独立的安装认证凭据；管理员密钥只用于服务器管理，绝不能发给客户端。

安装数不等于人数。清空或重建个人资料会产生新安装标识。用量记录数是 SDK 生成记录数，不是 HTTP 请求数。只累计聊天、视觉、闲聊及任务等大模型实际返回的 Token；缺失用量记为未知，各字段显示覆盖记录数。当前不统计 TTS／ASR 的时长或字符费用，不估算 Token，也不是服务商账单。

主进程将累计计数、安装身份和递增序号保存在当前个人资料目录，最近的观察 ID 用于去重；服务器只接纳新检查点的增量，重复重试不会增加用量。不要把同一份个人资料复制给不同用户，否则会共用安装身份。

给软件发布者与服务器管理员

另行提供 WoWCompanionDataHub-1.0.0-docker-source.zip。服务器安装 Docker Engine、Compose 和 Python 3，解压后进入包含 compose.yaml 的目录，依次执行 python3 setup.py、docker compose config、docker compose up -d --build。本地页面为 http://127.0.0.1:8080，管理员密钥由初始化脚本保存在 secrets/admin-key.txt，请在服务器本机查看。

对外提供服务前，按服务器包 README 配置自己的域名、HTTPS 反向代理，以及 .env 的 DATAHUB_ALLOWED_HOSTS、DATAHUB_PUBLIC_ORIGIN 和 Secure Cookie。应用端口仅绑定宿主回环地址。客户端只填写公开根地址；发布者也可在源码资源 apps/stage-tamagotchi/resources/wow-statistics.json 中配置 endpoint 后重新构建，仍须由每位用户完成告知。

已通过：服务器 Python 23 项、客户端与真实本机 HTTP／SQLite 服务集成 10 项、客户端协议与浏览器回归 50 项。部署包提供 Docker 配置，但本机没有 Docker，未执行容器启动验证。最终构建、归档哈希与新电脑验收结果以本次交付记录为准。

2.24.0 · 背包与银行物品 SQLite 仓库

插件读取背包及已打开银行中的装备、专业材料、宝石、配方、专业工具装备和制作成品候选，经原有 64×64 像素传输码送到陪伴精灵，写入本机 SQLite 数据库。所有可读物品的原始记录均保存，可在“全部物品”中查看。制作成品候选始终标记“来源未确认”：记录不能证明它来自实际制作、掉落还是购买。

更新后怎样查看

  1. 先从系统托盘正常退出旧版精灵，再运行本机原 Start-WoWCompanion.cmd，或完整解压本次 2.25.0 便携包后启动。
  2. 安装本次配套正式服插件 2.25.0，并保留更新前的备份与 SavedVariables。打开游戏插件列表启用插件，完整重新登录角色一次。无限服使用独立插件 1.21.0，按实际客户端目录手动复制；客户端接口仍需实机核对。
  3. 保持游戏画面中的数据码可见。登录后先采集背包；打开银行后，等待当前可读银行页面完成扫描。部分银行类型还需实际切换页面。
  4. 在“设置 → 魔兽世界正式服／无限服 → 角色档案 → 背包与银行物品仓库”点击“查看物品”，按角色、位置和分类筛选。输入名称或物品 ID 后点击“查询／刷新”，用上一页、下一页浏览。
  5. 展开“属性与词条详情”查看已传输的属性和提示文字。这里查询的是本地 SQLite，不向游戏发送搜索、移动物品或换装指令。

数据范围与完整性

  • 数据库按游戏版本、账号、角色、容器页面及格位区分。账号共享银行按账号保存，不为每个角色重复计算。
  • 专业分类使用客户端读取到的分类编号 3、5、7、9、19，对应宝石、材料、配方及专业工具装备等；另把消耗品 0、背包容器 1、物品强化 8 列为“制作成品候选”。“专业物品”同时包含两组，也可单独筛选候选。药水、食物、背包和附魔也可能来自掉落或购买，所以显示“来源未确认”，不推断实际制作。武器与护甲仍按装备查看，其实际制作来源也不作推断。旧记录或无法读取分类编号的物品标为“尚未分类”。
  • 银行必须在游戏内实际打开才可扫描。未打开或尚未扫描时显示“未扫描”，不会把未知内容当成空银行。历史银行记录会保留原扫描时间。
  • 未知格位或不完整页面保留上次已知物品，并标记“当前未确认”。只有完整可信的页面快照才能确认空格并清理对应旧行；不会因关闭银行或断线清空已有记录。
  • 传输码仍为 64×64 像素。跨语言模拟中，一个 34 格混合容器使用 83 个片段，轮播约 55.75 秒。首次扫描多页银行可需要数分钟，遮挡、缓存加载与重传会延长等待。
  • 仓库采用紧凑摘要：装备提示最多 4 行、每行 128 字节；非穿戴物品最多 2 行、每行 96 字节；属性最多 12 项。发生裁剪时明确标记“摘要已裁剪、部分词条未传输”，不承诺随后自动获得完整词条。穿戴快照与新获取装备的独立详情链路继续使用各自规则。

本地保存与备份

数据库默认位于 %USERPROFILE%\.airi-wow-companion\wow-companion-items.sqlite。自行设置了 APP_USER_DATA_PATH 时，数据库位于该资料目录。数据库保存物品实例链接、名称、数量、分类、属性摘要及观测时间。

通过软件数据页导出和恢复物品的逻辑记录，恢复时重新写入 SQLite，避免复制运行中的数据库及 WAL 文件。“删除所有数据”也会清空物品数据库；陪伴连接仍开启时，游戏资料可再次采集并写入。需要保持空库时，先关闭对应游戏连接。

  1. 在设置中打开正式服或无限服的使用向导，选择该客户端目录。选择包含客户端程序的版本目录，不是整个硬盘。

  4. 回到对应版本的陪伴设置，开启“陪伴连接”。程序会自动管理桥接，无需另开桥接窗口。

  1. 正式服输入 /wowc compact，无限服输入 /wowf compact。让数据码使用紧凑显示。
  2. 打开对应版本的连接与校准设置。按页面说明使用自动校准，或填写编码区的桌面物理坐标和每格大小。
  3. 若手动校准，使用 /wowc status 或 /wowf status 查看插件位置，并核对窗口边框、屏幕缩放和显示器位置。
  4. 保存校准后，核对角色名、等级、地图等信息。更换显示器、游戏窗口位置或显示缩放后，再检查校准。

紧凑数据码默认占用 64×64 像素，每格 1 像素。不要用窗口或其他游戏界面遮住它。无限服的接口和客户端显示仍需在实际客户端中核对。

“插件中心”右上角设置可分别保存游戏版本目录。通过 CurseForge 下载其他插件还需单独配置其开发者 API Key；陪伴插件的手动安装不依赖该 Key。

4. 这样使用陪伴功能

  • 日常聊天：在角色旁展开聊天，输入问题。精灵使用最新登录的游戏角色名称呼你。
  • 查看装备：登录及获取新装备时同步穿戴资料。可问“我现在穿的腿甲是什么”。记录属于对应角色和游戏版本。
  • 换装提醒：符合提升规则的新装备会触发询问。选择“好”后，仍需在游戏内点击确认换装。
  • 定时闲聊：在“设置 → 闲聊设置”分别控制普通闲聊、截图闲聊与地图逸闻。普通闲聊采用时间与真实脱战次数双条件。截图闲聊默认关闭，开启后会消耗模型额度。
  • 按需看画面：先在游戏打开装备提示或需要查看的界面，再说“看看这个”“看看我的装备”。系统截取游戏窗口，并将画面用于本轮对话。
  • 截图传递：可接收图片的聊天模型获得原图，纯文本模型按视觉设置使用描述。已有图片附件时优先看附件，不再额外截取游戏。
  • 语音字幕：播报时显示气泡。播放结束后，气泡按现有规则延迟 3 秒隐藏。静音和战斗免打扰按设置生效。

截图功能读取魔兽世界窗口，不是持续观看桌面。新的相机角度或界面需要再次发起查看请求。仅文本聊天不要求开启截图功能。

2.23.1 · 长期记忆容量与温柔提醒

桌面程序升级至 2.23.1。配套桥接与正式服插件仍为 2.23.0，无限服插件仍为 1.19.0。

下次开机后怎样使用

  1. 先从系统托盘正常退出旧版，再双击原来的 Start-WoWCompanion.cmd。保留原个人资料目录，不用重新填写模型凭据。
  2. 打开“设置 → 记忆与关系”，查看当前精灵的长期记忆已用条数和上限。
  3. 需要扩容时，填写新的整数上限并点击“保存容量”。需要整理时，逐条选择“忘记”，或取消非偏好条目的长期收藏。
  4. 如果配套插件早于 2.23.0，请更新正式服插件与桥接，并完整重启游戏、登录角色一次。已使用本轮配套版本时，无需再次替换插件。

容量怎样计算

每位精灵默认可保存 1000 条长期记忆，上限可设置为 100～100000 的整数。长期偏好和已收藏条目共用容量，去重后每条只计算一次。普通经历仍使用独立的 100 条保留规则。

容量满时，已有长期记忆继续保留，只暂停保存新的长期偏好与收藏。普通游戏记录和聊天仍可继续。调低上限不会自动删除现有记忆；手动整理或扩容后，即可继续保存长期内容。关系分数不会因整理记忆下降。

两种提示各代表什么

本轮没能全部想起：只有当你明确提问，匹配到的相关长期记忆超出本轮记忆选取预算时，才触发委屈、无助语气的提示：

“唔……我的记忆一次能容纳关于你的东西很有限，但我会尽可能地记住关于你的一切。这次没能想起的记忆，还好好保存在本地。”

当前记忆上下文最多带入 6 条，其中偏好最多 2 条、当前目标最多 1 条；每条文字最多 280 字，装备使用名称、装等和最多 6 项属性等摘要。这是软件的记忆预算，不是检测模型真实 token 窗口溢出，也不表示记忆已经被删除。其他角色、已隐藏和已过期内容不会冒充本次遗漏的相关长期记忆。

长期容量已满：使用伤感、不舍的固定文案说明需要整理，并明确保留选择权：

“有些舍不得呢……我得忘记一些关于你的记忆，才能记下新的故事、继续陪伴你。我还没有删除任何记忆，你可以选择整理，也可以扩容，让这些回忆留下来。”

两种提示按每位精灵、每种类型、本机日期每天各最多一次记录在主进程。重启不会重播当天已消费的提醒。不会因为刷新页面或桥接轮询频繁重复提示。

什么时候说、怎样说

收到真实用户提问后，提示等待当前对话与语音空闲；已知角色处于战斗时，等待脱战稳定 10 秒。配置了可用语音服务且未静音时，使用语音与现有字幕气泡；没有语音配置或处于静音时，只显示文字气泡。

提示使用固定的多语言文案，不调用聊天模型，也不消耗普通闲聊的分钟间隔或脱战次数。语音合成本身仍按所选服务计费。委屈与伤感通过文案表达，实际 TTS 情绪表现取决于服务和音色。

本次新功能的最终构建、自动化检查和发行包校验结果见本次交付记录。自动化边界使用模拟，真实游戏、模型服务和音频输出仍需按本文步骤验收。

记忆与关系，以及有话题才开口的闲聊

打开“设置 → 闲聊设置”。普通闲聊默认每 5 分钟检查，并要求自上次互动起完成 5 次真实脱战；可改为 2～30 整分钟与 5～30 次。分钟按现实时间计算，战斗也计时；角色须连续脱战 10 秒、在线且空闲后才检查。没有相关新话题就不请求模型，不消耗累计次数。

话题使用当前目标、收藏装备、重返地图的旧经历或近期明确经历，同一话题不反复询问。配置语音则语音加字幕气泡，未配置语音则仅文字气泡。截图闲聊在同一设置页独立开关与设置 1～60 分钟，普通闲聊不截图。

在“设置 → 记忆与关系”或闲聊页的“查看和管理记忆”进入管理页（/settings/wow-memories）。每位精灵最多保存 100 条普通记忆；偏好与收藏长期保留。游戏事实区分版本、账号与角色。正式服与无限服各自合计保留最近 10 条装备获取记录；记录标明所属角色，长期装备收藏另存。

可以编辑自己的文字、收藏、停止主动提起或忘记记录。当前临时目标绑定游戏登录，重新登录后失效；停止主动提起的内容不会继续被闲聊召回。日记由本地记录整理，不额外请求模型。

5. 角色形象与声音

包内已有 Hiyori（Pro / Free）Live2D 预设与 AvatarSample_A / B 的 VRM 预设。新资料目录的默认角色使用 Hiyori Pro。更换外观可在角色模型页选择预设，或导入你自己的模型。

本机以前导入的希尔瓦娜斯形象、参考音频、自定义音色及提示词属于个人资料，不会自动出现在另一台电脑的全新配置中。角色模型可通过软件的导入导出功能迁移，也可在新电脑重新导入完整模型文件。服务凭据、参考音频和音色配置需在新电脑分别检查。

Live2D ZIP 需包含有效的模型描述文件、模型数据与贴图，只有图片的压缩包不能作为完整 Live2D 模型导入。VRM 预设和自有模型也需选择对应的模型格式。

预设模型保留随附说明与许可证。自定义模型和音频按各自许可使用；外观资源的许可不替代模型服务的使用条件。

6. 资料保存、更新与迁移

默认个人资料目录是 %USERPROFILE%\.airi-wow-companion，例如 C:\Users\你的用户名\.airi-wow-companion。它与程序解压目录分开。程序文件夹可以移动，个人资料默认跟随当前 Windows 用户保存。

以后更新软件

  1. 从系统托盘选择退出。确认旧程序已关闭。
  2. 将新版本完整解压到另一个文件夹。保留旧程序，直至新版本完成检查。
  3. 启动新版本。使用同一个 Windows 用户和同一资料目录时，程序继续读取已有配置。
  4. 检查服务、角色形象和游戏连接。按新版本说明更新对应客户端的插件。

将个人配置迁移到另一台自己的电脑

  1. 从两台电脑的系统托盘正常退出程序，再复制资料。
  2. 在旧电脑备份完整的 .airi-wow-companion 文件夹。
  3. 在新电脑找到相同的用户资料路径。如果已有资料，先另行备份。
  4. 将备份放入新电脑的 %USERPROFILE%\.airi-wow-companion，再启动软件。
  5. 重新检查模型服务凭据、参考音频、本地模型路径、游戏目录和传输码校准。路径不同或不可用的文件需重新选择。

个人资料备份包含密钥、聊天和账号记录。只在自己的电脑间迁移，不要把它放入公开分发的程序包。本次交付包不包含这些资料。

若启动时自行设置了 APP_USER_DATA_PATH，以该路径为准。更新前先核对实际使用的资料目录。
