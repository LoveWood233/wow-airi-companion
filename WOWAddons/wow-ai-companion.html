PROJECT BRIEF / 研究与开发方案

让艾泽拉斯的冒险
多一个懂你的伙伴。

基于《魔兽世界》的多模态智能陪伴系统：结合插件数据、画面理解和自然语言交互，提供有依据的游戏建议与个性化陪伴。

方案整理 · 2026.10.18主要参考 · 正式服形态 · 游戏插件 + 桌面伴侣 + AI 服务
01 / DATA

API 获取准确事实

角色、任务、地图和装备优先读取结构化数据；属性差值使用代码计算。

02 / VISION

视觉补充画面信息

理解眼前的环境、建筑和任务物体，支持用户主动发起的截图问答。

03 / COMPANION

AI 负责理解与陪伴

结合可靠资料与玩家目标生成解释、攻略回答、祝贺和冒险回忆。

实施边界：本方案是可行性与范围设计，尚未完成客户端实测。正式服与各怀旧服分支的接口不同，开发前须固定地区、版本及构建号。API 可读不等于可在所有场景自由计算；外部视觉辅助也不等于获得官方许可。

01

先区分两类官方接口

IN-GAME / 游戏内

WoW AddOn API

在客户端 Lua 沙箱内运行，读取允许访问的角色、装备、任务、地图与事件数据，创建精灵窗口和交互界面。

限制：没有通用 HTTP / WebSocket 能力，不能任意读写文件；部分战斗信息受 Secret Values 等机制限制。

WEB / 游戏外

Battle.net Web API

由外部程序调用，适合补充物品资料、角色档案、成就和收藏等数据。

限制：不是当前游戏状态的实时流；地区、版本、权限和端点覆盖需要验证。查看开发者门户 ↗

03

首个完整场景：新装备与成长反馈

把“事实计算”“收益判断”和“陪伴表达”分开，确保情绪价值建立在准确的信息上。

STEP 1 / 确定事实

属性变化

对比新旧物品的属性，明确装备槽位、比较对象和实际穿戴状态。

产出：属性增减、物品等级差值。

STEP 2 / 条件判断

收益解释

结合职业、专精、属性权重，以及套装、饰品等特殊效果评估。

产出：带条件的建议或模拟估计。

STEP 3 / 陪伴表达

个性化回应

根据确定的变化和玩家此前设定的目标，生成自然的祝贺与说明。

产出：简短、可信、可关闭的反馈。

示例话术 · 以下数值仅用于说明
“这件装备相比你当前这件，多了 120 智力和 80 急速等级。之前你想补急速，这次掉落正好有帮助！不过最终输出收益还要结合套装效果来看。”

属性增加百分比 ≠ DPS 增加百分比。物品等级更高也不保证实战更强。计算模块提供事实，语言模型负责解释。

04

系统架构与通信边界

A / 游戏插件

采集与基础交互

  • 读取允许访问的角色、任务和装备数据
  • 监听事件、计算属性差值
  • 显示基础精灵与状态面板
  • 导出可复制的数据摘要
B / 桌面伴侣

截图与服务协调

  • 接收导出文本和用户输入
  • 捕获游戏窗口与裁剪画面
  • 调用模型、保存偏好和历史
  • 显示 AI 回复与播放语音
C / AI 服务

感知与内容生成

  • 视觉理解与文字识别
  • 检索匹配版本的攻略资料
  • 融合结构化数据与截图
  • 生成建议、陪伴与日记
实际数据流：插件摘要 → 用户复制或实验性屏幕识别 → 桌面端 → AI 服务 → 桌面端回复。
桌面端截图可直接输入视觉模型。当前方案不假设存在“外部 AI → 游戏内插件”的通用实时回传接口。
连接方案适用范围主要限制
手动复制导出文本角色、任务、装备分析原型需要用户操作，但容易核对数据与验证链路。
识别插件摘要面板非战斗场景的近实时上下文采集实验处理 OCR 误差、遮挡和 UI 缩放；不是官方外部通信接口，不用于恢复受限战斗数据。
读取已落盘的历史数据冒险日记与离线统计不适合作为实时对话通道；数据有保存时点限制。
为什么不能让 Lua 插件直接调用大模型？

WoW 插件处于受限沙箱，没有通用 HTTP / WebSocket 能力，不能像普通桌面程序那样访问本地服务或互联网。SavedVariables 通常在退出或重载 UI 时落盘，不能当作实时消息队列。C_ChatInfo.SendAddonMessage 面向游戏客户端之间的插件消息，也不是本地 Python 服务接口。

AI 回复显示在哪里？

建议第一版显示在桌面伴侣窗口或独立浮层中。游戏内精灵可以展示本地规则与模板生成的提示。若要求外部 AI 回复自动进入真正的插件气泡，需要额外解决回传问题，不能通过“增加一个本地服务器”就认为问题已解决。

05

实时能力的范围

适合第一阶段

任务、探索与装备建议

采用事件触发或用户按键触发分析，允许秒级响应。装备计算先在本地完成，再生成解释。

视觉结果携带置信度；上下文过期时重新采集，资料不足时明确说明。

独立研究范围

即时战斗指挥

打断、躲技能与技能循环既受模型延迟影响，也受正式服战斗数据限制。

先使用录制视频做离线实验，避免把实时战斗决策列为可直接上线的能力。

官方政策边界：暴雪说明部分战斗状态可被插件显示，但不能被自由分析。用视觉重新识别受限信息，并不自动获得官方许可；外部辅助的具体用途需另行核实。参考战斗与插件设计说明及第三方软件公告。

06

第一版开发范围

用六个功能形成可演示闭环：识别上下文 → 提供帮助 → 回应成长 → 留下记忆。

陪伴精灵与设置

形象、气泡、提示频率、安静模式；明确插件与桌面端各自显示的内容。

角色与任务上下文

采集角色、位置和任务进度，展示可核对的摘要，先打通手动导出链路。

装备分析与祝贺

准确比较属性变化，结合用户目标生成简短反馈，避免重复触发。

有来源的攻略问答

检索匹配版本、职业和任务的资料；回答附来源，资料不足时不编造。

主动截图问答

由用户触发截图，理解探索场景、任务物体和界面问题。

冒险日记与记忆

总结当日真实进展，记住玩家主动设定的目标，提供删除入口。

建议开发顺序：固定版本与接口验证 → 插件采集和装备计算 → 桌面端导入与聊天 → 截图分析 → 个性化陪伴 → 实验评估。第一版不必同时引入语音、精确 DPS 模拟与实时战斗建议。

07

论文题目与实验设计

建议题目

基于多模态感知的《魔兽世界》智能陪伴系统设计与实现

研究问题：结构化游戏数据与视觉信息融合，能否提高智能陪伴建议的准确性与用户体验？

实验 A：多模态信息的价值

对照条件：仅 API、仅视觉、API + 视觉。

控制变量：使用相同任务、资料库、模型配置与输出要求；对不同类型任务分别统计，避免用偏向某一输入方式的任务得出笼统结论。

指标：场景识别准确率、建议正确率、响应延迟、调用成本、无法判断的比例。

实验 B：陪伴表达的价值

对照条件：固定模板、基于相同事实的个性化 AI 回应。

控制变量：保持触发事件、频率和事实内容一致；平衡体验顺序，结合问卷与访谈评估。

指标：陪伴感、帮助程度、可信度、打扰程度及继续使用意愿。

需要保留的实验记录

客户端版本、任务与场景标签、API 快照、截图时间、资料来源、模型与提示词版本、响应时间、输出内容和人工评分依据。区分“截图采集时间”与“模型完成时间”，防止使用过期场景评价实时建议。实验截图与对话记录应获得参与者同意，并遮蔽无关聊天及身份信息。
