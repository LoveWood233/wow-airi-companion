MEASUREMENT · 统计口径

按实际返回用量累计

用量记录数是 SDK 生成记录次数，不是 HTTP 请求次数。聊天、视觉、闲聊、任务等大模型返回用量时才累计相应 Token；缺失用量记为未知，各字段独立提供覆盖次数。

不按字数估算。TTS／ASR 的字符、时长等费用未纳入当前 Token 统计。这是客户端自报记录，不是完整账单、扣费或结算依据。

实现逻辑

01 · 用户确认

先告知，再收集

原生主进程同时检查告知状态和开关。服务地址为空时不联网；发布包预填地址也不能绕过告知。

02 · 本地累计

只接收无内容用量

每次 SDK 生成产生随机观察 ID 和已报告字段，主进程串行保存累计值。近期8192个观察 ID 用于去重。

03 · 每300秒

上传累计检查点

登记、启用或变更地址后可先发送；正常运行每300秒发送。先保存递增序号再联网，服务器离线时保留本地累计，后续重试补传。

04 · 服务端合并

只累计新增用量

每个安装独立认证。服务端保存检查点，以累计差值入库；重复序号重试不重复增加，旧序号忽略，计数回退拒绝。

客户端统计文件位于当前个人资料目录的 wow-installation-statistics-v1.json，与程序解压目录分开。关闭统计后停止新增收集和上报，之前已发送的汇总保留在服务器。不要把同一份资料复制给不同用户，否则会共用安装身份。清空或重建资料后会生成新标识。

03B / GOLD LEDGER

账号金币怎样统计

以铜币为最小单位：1 金 = 100 银 = 10,000 铜。界面显示金、银、铜，不使用浮点小数累计。

先赚后花，分别入账

插件首次读取已有 100 金，只显示为余额。之后获得 3 金、花掉 2 金，即使两次变化都发生在一次桌面采集之前，累计流入仍是 3 金，流出是 2 金，净变化是 +1 金。

插件保留累计数，魔兽陪伴精灵只加入尚未记过的差额。魔兽陪伴精灵首次连接会导入插件已有累计收支。关闭魔兽陪伴精灵后继续游玩，只要插件仍在采集且计数未丢失，下次连接会补上这段累计变化。

账号与余额的范围

同一账号 SavedVariables 下的角色会归为一组。你可以把自动标识改备注为“主账号”“小号账号”。这个功能不读取战网邮箱、密码或登录信息。

已知余额合计只包含本机观察过的角色，取各自最后一次余额。未登录角色、战团银行和公会银行的余额不在其中。

理解收入与消耗：统计的是角色钱包流入和流出，包含邮件、交易、修理、购买和银行存取。自己的角色之间转账会分别出现流出和流入；它们不等于纯收益或物品购买分类。此次不按日拆分，也不推断交易原因。
保留数据：不要删除插件 SavedVariables 或魔兽陪伴精灵本地账本。清空插件保存文件会产生新的账号标识；把该文件复制给不同账号会复制标识。游戏异常退出前尚未保存的变化，以及插件未运行时的变化，无法完整追回。若恢复旧 SavedVariables 导致同一计数段的累计数回退，桌面会拒绝该角色的回退记录，直到收入和支出都追上已保存数值；此时账号汇总的最近采集时间不会更新，也不会自动补账。

01 · 必做 · 先确认程序能启动

启动新版魔兽陪伴精灵，让它自动管理采集

  1. 先正常退出旧魔兽陪伴精灵。本次 2.6.0 更新桌面、桥接和插件，旧进程不会自动加载新功能。启动脚本提示 already running 时不会替换旧进程。本机从 2.5.0 更新后可在游戏内执行 /reload；首次安装或更早版本缺少 ConfirmEquip.lua 时需完整重启游戏。
  2. 打开文件夹 I:\GameTools\WOWAddons，双击 Start-WoWCompanion.cmd。正常模式只启动魔兽陪伴精灵，不必单独打开桥接。当前电脑已有源码、桌面依赖和 Python 3.10+，正常使用不必重复安装。
  3. 在魔兽陪伴精灵角色右侧点击展开箭头，再点击齿轮“打开设置”，进入 魔兽世界正式服。开启陪伴连接并保存。等待连接成功；未登录游戏时会显示等待状态，登录并校准后显示真实在线。若出现错误，按下方排错表处理；程序会延迟重试。
  4. 需要查看采集预览时，再打开 本机桥接校准页。没进入游戏时出现“等待游戏”正常。保留角色主窗口运行；关闭设置窗口不会停止连接。
  5. 退出与重新开启：关闭陪伴连接或正常退出魔兽陪伴精灵后，它自己启动的桥接会停止。再次开启连接或启动魔兽陪伴精灵后会自动恢复。若你此前单独启动了兼容桥接，魔兽陪伴精灵会复用它；退出魔兽陪伴精灵不会停止那个服务，需由原启动方式管理。

成功标志：只启动魔兽陪伴精灵并开启陪伴连接后，连接没有报错，本机桥接网页可打开。此时没有角色数据也可以继续。若连接已关闭，自动桥接随之停止，网页打不开属于正常情况。

02 · 必做 · 需要你登录正式服角色

启用插件，并确认黑白网格正在更新

  1. 使用正式服插件 2.9.0，并在游戏中执行 /reload 加载。首次安装或新增模块时，完整退出并重新启动游戏。配套桌面和桥接版本为 2.10.0。
  2. 在插件列表勾选 魔兽陪伴精灵 / 魔兽陪伴精灵桥接（英文名 WoW Companion / AIRI Bridge）。安装位置是 I:\Game\World of Warcraft\_retail_\Interface\AddOns\WoWMapCompanion，无需再次复制文件。
  3. 登录角色，确认只显示黑白数据传输码，地图、角色和金币文字面板已经消失。在聊天框依次输入下方两条命令，每条输入后按回车。
/wowc selftest
/wowc status

没有网格时：先看 /wowc status。只有显示遥测关闭时才输入一次 /wowc telemetry；这条命令是开关，重复输入会再次关闭。若位置被移出可见范围，可用 /wowc pos 8 8 和 /wowc cell 2 恢复常用位置与尺寸。

没有插件或提示版本不匹配时：确认启动的是 _retail_ 正式服，插件目录没有套两层。客户端升级后先记录 /dump select(4, GetBuildInfo()) 的输出发给我核对；不要只改接口号就把它视为兼容。

成功标志：自检通过，状态信息中的角色等级正确；隔几秒再次执行 /wowc status，可见心跳递增，屏幕上有完整网格。插件自检通过只说明编码正常，还要完成桌面采集校准。

03 · 必做 · 需要实际分辨率和显示器布局

让桌面捕获区域准确对齐游戏网格

缩小传输码：游戏内输入 /wowc cell 1，桥接页“每格像素”同步设为 1，即可缩至 64 × 64 物理像素。当前插件已修正屏幕分辨率和 UI 缩放导致的额外放大；首次更新旧版后需 /reload。主屏无边框、插件位置为 (8,8) 时，桥接填写 X=8、Y=8。窗口模式需加上客户区偏移；如单像素受到缩放或 HDR 干扰，可将两端都改回每格 2 像素。

  1. 第一次校准建议把 WoW 放在主显示器、无边框窗口模式，游戏画面保持可见。把魔兽陪伴精灵、浏览器和其他窗口移开网格所在区域，避免截图采到它们。
  2. 在游戏里运行 /wowc status 记下位置和每格尺寸。默认位置为游戏客户区左上 (8, 8)，每格 1 像素，总大小 64 × 64。已有位置保留。
  3. 打开本机桥接页。主屏无边框、游戏客户区原点为 (0, 0) 且插件位置为默认 (8, 8) 时，填写屏幕 X=8、屏幕 Y=8、每格像素=2、轮询毫秒=100，点击“保存校准”。若页面显示“恢复采集”，再点击它恢复采集。当前本机插件使用 Y=32，以实际状态为准。
  4. 点击刷新预览。预览应恰好包含完整的 64×64 黑白格：没有标题栏、边框、背景，也没有切掉边缘。预览是点击时取得的截图，调整后要再次点击。
  5. 窗口模式或副屏上，填写的是桌面物理坐标，不能直接照抄插件坐标。计算方式：桌面采集 X/Y = 游戏客户区在桌面上的物理起点 + 插件 X/Y。例如客户区起点为 (200, 120)，插件为 (8, 8)，则填 (208, 128)。左侧/上方副屏可能使用负坐标。
  6. 也可以在魔兽陪伴精灵“魔兽世界正式服 → 屏幕位置校准”中填写同样数值并点击应用校准。截图预览在本机桥接网页中查看。两边编辑的是同一份桥接配置，选一处修改即可。

网格模糊、CRC 失败或一直等待：先核对坐标、遮挡和两端每格尺寸。如果网格边缘混入灰色或游戏背景色，进入游戏系统 → 图形，先切到窗口模式并应用，再切回全屏（窗口化）并应用，使用显示器原生分辨率；随后输入 /reload 重建游戏布局，再重新校准并刷新预览。游戏报告分辨率与 Windows 实际客户区不一致时，整幅画面会被再次拉伸；本机曾为 2560×1440 与 2576×1460，重新应用显示模式并重载后恢复一致，64×64 网格成功实时读取。若仍失败，检查 UI/Windows 缩放及 HDR，或将两端都恢复为每格 2 像素。不要只在一端改尺寸，也不要仅靠放宽校验阈值掩盖缩放问题。

历史校准：此前已用 X=8、Y=32、每格像素=2 恢复持续实时读取，网格面积为 128×128 像素。当时单像素画面出现模糊与 CRC 失败，因此曾使用两像素单元格。新版默认改回单像素，并提供严格校验下的局部自动识别；本轮未重载游戏，不将此前结果算作新版实测。移动网格、切换显示器或改变窗口位置后仍需重新校准。

成功标志：桥接页显示“真实游戏 · 已连接”，魔兽陪伴精灵显示“真实角色在线”，姓名、等级、地图与游戏一致，连续观察约 10 秒仍保持在线。状态不能是“演示数据”或“上次已知状态”。

04 · 文字陪伴必做 · 服务选择和凭据由你提供

配置对话服务，并真正选中一个模型

  1. 先进入 设置 → 魔兽陪伴精灵角色卡，确认标有“当前使用中”的陪玩角色。然后确定你要使用、且已经可用的对话服务。云服务需要你自己的账户/访问凭据；本机模型服务需要你先启动服务并加载模型。本轮没有替你开通账号或选择付费套餐。
  2. 首次欢迎页可点配置您自己的 AI 服务来源；已有角色窗口则进入设置 → 服务来源 → 聊天，选择与你的服务一致的提供方。
  3. 按该提供方页面填写 API Key、服务地址等必填项；本机服务按页面要求填写地址。服务地址和模型标识以你所用服务的实际配置为准，不要随意增删路径。凭据直接填在魔兽陪伴精灵中，不需要发给我。按页面完成验证，看到“配置验证成功”或相关检查项“通过”后再继续。
  4. 进入设置 → 机体模块 → 意识，选择刚配置的服务来源，再选择一个实际可用的对话模型。若提供方不支持列出模型，在页面提供的“模型名字”栏填写准确模型 ID，并核对“当前模型”显示正确。仅填写 Key、没有选模型，仍然无法回应。
  5. 回到角色主窗口，打开聊天，输入“请用中文简单问候我。”，确认能收到正常文字回复。再在真实角色在线时问“我现在多少级，在哪张地图？”，核对回答与陪伴页一致。

切换角色卡后要复核：角色卡可以保存独立的对话/声音选择，显式配置会覆盖继承值。进入 设置 → 魔兽陪伴精灵角色卡 → 当前角色 → 卡片编辑 → 模块，检查“聊天”和“语音”；需要统一配置时选择“继承全局设置”，需要独立配置时明确指定提供方、模型和声线，再点“保存更改”。换卡后重新核对“意识”和“发声”。

成功标志：普通聊天能回复中文，陪伴页不再提示“请选择对话服务和模型”。普通聊天未通过前，不必反复触发游戏升级来排查。

05 · 语音陪伴必做；麦克风输入可选

先让角色能说话，再按需开启听觉

  1. 配置语音输出：进入 设置 → 服务来源 → 语音合成，配置你使用的 TTS 服务。对话模型可用不代表语音合成也已配置，这通常是两个独立设置。
  2. 进入 设置 → 机体模块 → 发声，选择语音服务、该服务支持的模型和声线；若服务需要手填声线 ID，填写其实际 ID。不要选择“无／不使用语音合成”。声线区域可能显示英文 Voice Configuration 或 Current voice，更换语音服务或模型后要重新核对声线。
  3. 在发声页下方实验平台输入“欢迎回到艾泽拉斯，我们继续冒险吧。”，点击测试声音，播放生成的音频。确认中文发音和音量正常。
  4. 回到魔兽陪伴精灵主窗口，确保扬声器没有静音；检查 Windows 音量混合器中魔兽陪伴精灵/Electron 的音量及当前耳机/扬声器。再发一条普通聊天，确认同时有文字和声音。
  5. 可选语音输入：如果希望直接对精灵说话，先在 设置 → 服务来源 → 语音识别 配置 STT 服务，再进入 设置 → 机体模块 → 听觉 → 语音识别 选择服务、模型和麦克风。在“听觉测试面板”点击开始监听，由你允许需要的麦克风权限，说一句短句，检查转写文字；结束后点击“停止监听”。
  6. 听觉测试通过后，回到“听觉”页开启麦克风，选择持续聆听、按住说话或唤醒词方式，再使用主窗口“打开麦克风”。若“自动发送”关闭，需要手动发送转写稿；选择唤醒词方式时，要先配置并说出唤醒词。只需要精灵播报时，可以不配置听觉，也不必打开麦克风。

成功标志：发声测试和普通聊天都能听见声音。若还需要语音输入，说话能形成准确文字并进入对话；仅听见声音不代表麦克风链路已通过。

06 · 建议先做 · 不用等待真实升级

用演示分别验收数据、文字回应与语音

  1. 进入 设置 → 魔兽世界正式服，开启“开启陪伴”“升级时祝贺”“进入新区域时回应”“死亡后安慰”“复活后鼓励”；关闭“游戏提醒静音”，点击“保存陪伴偏好”。
  2. 若只验证数据，不必开启“允许角色回应演示事件”。若要验收 AI 文字/语音，先完成第 4～5 步，再明确打开允许角色回应演示事件并点击保存陪伴偏好。此时演示回应会使用你配置的模型和语音服务，按该服务计费规则运行。
  3. 点击开始演示，看到“演示数据”和演示角色后等待至少 2 秒，让主窗口建立基线。不要刚开始演示就连续点击事件按钮。
  4. 点击一次模拟升级，确认等级从 29→30（或从当前演示等级升一级），最近事件中只增加一条相应升级记录。允许演示回应时，等待角色给出简短祝贺，并明确这是演示/测试。
  5. 默认两次回应最小间隔为 20 秒。等上一次回应结束且间隔已过，再分别测试“模拟死亡”“模拟复活”“切换区域”。事件记录出现只代表已识别事件，不保证已经生成声音。
  6. 测试战斗免打扰：确保“战斗时免打扰”开启并已保存，切换到战斗状态后触发一次升级，再于 30 秒内切回非战斗，观察近期提醒是否在允许时机回应。超过 30 秒的事件会被丢弃；角色正在生成其他回复时，提醒也可能被跳过。
  7. 结束后点击返回真实画面采集，关闭“允许角色回应演示事件”并保存；若临时改变了冷却时间，恢复到 20 秒。确认页面重新等待或显示真实角色。

成功标志：数据模式下事件正确且不误当真实游戏；允许演示回应后有文字回应，配置声音后可听见；退出演示后真实数据重新建立基线。无需为了测试死亡鼓励让真实角色故意死亡。

07 · 最终实机验收 · 在自己的正常游玩过程中完成

确认真实事件能到达精灵，并检查免打扰

  1. 先核对基线：关闭演示，保持真实角色在线至少 10 秒，确认等级、地图一致。初次连接或 /reload 后只有基线记录，不应因为“已经有这个等级”就祝贺一次。
  2. 先测容易触发的区域变化：步行跨到不同地图 ID 的相邻区域，保持网格持续可见，检查区域更新及事件。只走进同一地图内的小地名不一定有变化；带加载画面的传送可能重建基线，不用它作为第一次必达提醒测试。
  3. 测试游戏上下文：在魔兽陪伴精灵聊天里问“我目前的等级和地图是什么？”；回答应与陪伴页显示的信息一致。若模型答错，保留当时的界面和回复供排查。
  4. 测试真实升级：用尚可升级的角色正常游玩，升级前让桥接保持在线，升级时不重载插件。观察等级自动变化、出现一条升级记录，并在静音关闭、冷却允许、角色空闲时收到回应。满级角色可先完成区域验收，把真实升级记为待测。
  5. 死亡/复活：在正常游玩自然发生时核对两种状态和事件；不用专门制造死亡。若开启战斗免打扰，应按战斗状态、冷却和 30 秒有效期判断是否有主动回应。
  6. 测试断流：先确认遥测开启，然后输入一次 /wowc telemetry 关闭，等 6 秒；状态应不再是实时在线。再输入一次恢复，等待重新在线。恢复只建立基线，不补播断流期间的升级。
  7. 测试静音：开启“游戏提醒静音”并保存，再正常切换区域。信息和事件仍应更新，但不主动发送新的游戏回应；已经开始播放的语音不一定被这个开关中断。测试完按自己的偏好保留设置。

勾选用于你本次阅读时记录进度，不会自动上传，也不保证刷新页面后保留。未实际完成的项目请保持未勾选。

08 · 新增 · 在正常游玩时核对

查看每个账号的金币获取与消耗

  1. 启用新版：当前组合为正式服插件 2.6.0、无限服插件 1.3.0、桥接 2.6.0、魔兽陪伴精灵二开 2.6.0，仍使用 v2 金币协议。本轮需正常退出旧魔兽陪伴精灵后重新启动。首次从 2.0 升级时，还需完整重启游戏以加载金币模块；启动脚本不会替换已经运行的旧魔兽陪伴精灵进程。
  2. 查看首个账号：打开魔兽陪伴精灵“设置 → 魔兽世界正式服”，保持真实采集在线。找到金币汇总，核对当前角色余额与游戏背包的金、银、铜一致。刚开始记录时，原有金币不会成为收入。
  3. 设置账号备注：在账号卡片填写易辨认的名字，例如“主账号”，点击保存。备注只改变显示名称，不改变游戏账号或角色。
