# 任务遥测：插件到桌面的链路验证

本记录覆盖第 4 项的双端只读任务采集、独立分片、Python 状态拼装及桌面 TypeScript 契约。任务检索、助手页面、聊天卡和主动提醒由各自专项验证记录说明。

## 已实现与边界

- 正式服与无限服各新增 `Quests.lua`，使用共同的 `C_QuestLog` 读取日志、任务标题／等级／可见地区标题、目标原文与公开进度、目标就绪及失败标记。不展开日志，不接交／放弃任务，不设置导航，不执行游戏输入。正式服只传实际观测，不接无限服资料。
- 共享契约为 `airi/apps/stage-tamagotchi/src/shared/wow-companion-quests.ts` 的 `QuestSnapshot`。主心跳 v3 不增加字段；任务通过 `qlog` 独立分片，按 session／GUID／单调 id 修订隔离，保留 `observedAt`。桥接状态增加必填可空 `quests`、`questsReceivedAt`、`questsError`。
- `log.complete` 和 `objectivesComplete` 仅描述读取覆盖完整，不代表任务／目标成功。`readyForTurnIn` 是目标就绪，不代表交付。不可读字段为 null，API 不可用、日志折叠／隐藏或截断时明确 partial／unknown，不把未知当零或空日志。
- 完成 API `GetAllCompletedQuestIDs` 只提供客户端完成标记；文档未证明其历史记录属于当前角色还是账号，所以 `completion.scope` 固定 unknown。只有 `QUEST_TURNED_IN` 生成当前会话的真实交付回执。移除任务、关闭对话、目标完成或完成标记都不能生成交付事实，列表缺席也不能证明未完成。
- 单份最多 50 个日志任务、每个 8 个目标、512 完成标记、32 去重交付回执，UTF-8 JSON 最多 32 KiB，单块最多 240 字节／137 块。超量有 truncated 标记，完整读取的 API 集合总数与保留数量分开；其 complete 不等于所有世界任务已完成。
- 最多两个独立在途修订，20 分钟绝对拼装／采集期限，未来容忍 120 秒；桌面自动提醒采取更严格的时间规则。只有拼完且校验成功才能替换，旧修订回放不刷新接收时间。新修订在途、断线、暂停、演示、错误或错角色时不提供当前任务。
- 事件合并采集；初次传输完成前不会重置为新修订，安静日志约每 60 秒重采。任务和背包轮流分享后台传输槽，新装备和比较保持优先，主心跳照常交替，任务事件不触发额外装备／位置刷新风暴。

## API 核实

无限服已通过只读 `wuxianwow.addon_api` 核实 `C_QuestLog.GetNumQuestLogEntries`、`GetInfo`、`GetQuestObjectives`、`ReadyForTurnIn`、`IsFailed`、`GetAllCompletedQuestIDs`，以及 `QuestInfo`、`QuestObjectiveInfo` 和 `QUEST_TURNED_IN` 字段。来源：[无限图鉴 wuxianwow.com 插件 API](https://wuxianwow.com/api/)。未根据经典客户端的旧印象启用 `GetQuestLogTitle` 等未核实回退。

正式服查阅了 Blizzard 生成的 [QuestLogDocumentation.lua 源码镜像](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/QuestLogDocumentation.lua)。实际代码仍逐个检查 API、pcall 读取及 secret／可访问表；版本缺失和受限读取不会借用其他版本状态或补造数据。

## 定向与回归证据

- 两版实际 Lua 5.1 任务测试各 11 项通过，覆盖读取、目标／完成／交付区别、移除、secret、折叠日志、负载与完成集合截断、身份切换、事件合并、安静刷新、退出和库存公平传输。
- 无限服 Lua 全量 207 项通过；正式服全量 200 项中 199 项通过，唯一失败是已有的两服 Localization.lua 必须逐字节相等检查（无限服额外探索提醒词条），不是任务遥测失败，本轮未改本地化目录。
- Python 桥接全量 257 项通过，其中任务新增 11 项；保留原装备、比较、库存、query-only 和 HTTP 检查。
- TypeScript 任务契约／库存契约／HTTP 客户端 3 文件共 44 项通过。真实双端链路为 Lua 采集→CRC 帧→Python 解码及会话拼装→整份 `/api/status` 结构 fixture→TypeScript `bridgeSchema`，不是仅手写同形对象。初轮并发负载下原客户端 1 秒网络轮询曾超时，单独复跑整组通过，没有因此放宽业务条件。
- 加上桥接 runtime 最低版本／自有进程检查，最终 4 文件共 76 项通过，无跳过；覆盖拒绝 2.16／2.17 老采集进程并要求 2.18。桌面 typecheck 通过。
- 定向 ESLint 包含全部 14 份补充合法 null 的既有 fixtures、新任务契约／测试和最小桥接版本检查，结果见日志；完整桌面构建与根 lint 由总验证记录确认。

## 使用前更新与待验收

当前源码版本为桥接 2.18.0、正式服插件 2.18.0、无限服插件 1.16.0。桌面采集 runtime 最低要求桥接 2.18，避免复用缺少新字段的旧进程。需要部署完整对应插件（含新增 Quests.lua 和 TOC），完整退出并重启游戏，再重启最新桌面构建与受管 Python 桥接。尚未部署或启动实际游戏，本轮没有个人模型／语音／真实接交任务验收，没有安装依赖、重新打包 Windows、push 或关机。
