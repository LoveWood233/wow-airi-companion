日期：2026-11-01。五项任务中的第 2 项，按用户确认的六类实体范围实现。

## 已实现

“正式服本地资料”设置页可选择已有导出 SQLite，查询物品、底层地图、世界地图、地区、技能和副本首领。支持搜索、分页、按 ID 查看详情、内部关联及快照统计。

陪伴模型默认可用的 `builtIn_wowRetailQuery` 使用同一只读接口，真实工具结果显示独立本地资料卡。资料卡与页面明确注明「正式服本地 DB2」、游戏版本、数据语言、导出时间、查询收到时间、快照标识和实际依赖表。没有伪造外部网页链接。

底层 `map:0` 是合法 ID；`map`、`uimap`、`area` 等命名空间分别处理。原始法术模板和未解释字段保留原值，不猜测最终效果。SQL NULL 不当成零，省略并提示缺失；空字符串仍保留为空字符串。

这些客户端资料不等于服务器当前行为。未叠加热修、加密分段、部分缺失字段和截断结果有明确提示；数据库不能证明角色任务进度、完整任务攻略、实时拍卖价格或无限服规则。

## 本地配置与运行

普通进入页面只读取已选路径配置，不打开数据库或启动查询进程。点击选库后，主进程先只读验证，成功后才激活；选错库保留原选择。取消选择会停止本功能拥有的查询进程，不删除源数据库。

用户选择有效数据库时，路径写入应用用户数据目录下的 `wow-retail-database-v1.json`。路径只在本地设置页展示，不进入模型结果。本次开发没有修改个人选库配置或 Codex 的 MCP 配置。

查询通过现有 Python 桥接的独立 `query-only` 模式运行，固定本机端口 `18767`，使用一次进程身份与 Token 校验。它不导入窗口采集模块、不创建采集线程、不启动游戏、模型或语音。关闭父进程管道会结束自己启动的查询进程，不复用或关闭其他服务。

只接受固定的 `search`、`fetch`、`stats` 参数。模型与页面不能提供 SQL、表名或数据库路径。Python 使用只读连接、固定白名单 SELECT、参数绑定、两秒扫描预算及结果上限，未建索引、改表、下载或更新源库。

换库时主进程与页面分别隔离迟到结果。重新进入页面不会锁死忙碌状态；取消文件选择不发起统计查询。草稿变化不会自动查询，也不能把原查询的下一页悄悄变成新查询。
