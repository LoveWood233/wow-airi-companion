## 一、产品定位

魔兽陪伴精灵是一款围绕《魔兽世界》游玩过程提供陪伴和辅助的 Windows 桌面应用。它以桌面角色为入口，结合玩家的角色状态、装备、金币和游戏事件，提供聊天、语音回应、信息查询与工具服务。

当前产品由三个主要部分组成：

| 组成 | 职责 |
| --- | --- |
| 游戏插件 | 读取公开角色信息，在游戏画面显示数据传输码，并提供游戏内换装确认。 |
| 本机桥接 | 读取传输码，校验、重组数据，向桌面端提供角色状态与事件。 |
| 桌面精灵 | 展示角色、进行对话与语音互动、保存记录，并提供插件中心、快捷启动和截图辅助。 |

## 二、当前已实现的功能

### 2.1 桌面角色与对话陪伴

| 功能 | 当前能力 | 使用条件或边界 |
| --- | --- | --- |
| 桌面角色展示 | 复用 AIRI 的角色形象、桌面窗口、角色菜单和配置能力。 | 实际形象由当前选择和导入的模型决定。 |
| 文字聊天 | 与当前角色进行对话，沿用所选角色卡和系统提示词。 | 需要配置聊天服务和模型。 |
| 语音回复 | 通过配置的语音服务朗读回复。 | 需要可用的语音模型、音色和服务凭据。 |
| 语音输入 | 使用已有语音识别能力，将说话内容送入对话流程。 | 需要配置识别服务及麦克风权限。 |
| 角色风格定制 | 通过角色卡调整说话方式、人设和互动语气。 | 人设与实际音色分别配置。 |
| 使用玩家角色名称呼 | 根据有效的实时角色数据更新称呼，切换角色后同步变化。 | 数据失效时使用中性称呼，演示角色不会覆盖真实角色。 |
| 语音字幕气泡 | 在桌面角色旁显示正在播放的语音字幕。 | 普通播报结束约 3 秒后隐藏，装备询问采用独立的选择计时。 |

### 2.2 游戏连接与角色信息

| 功能 | 当前能力 | 使用条件或边界 |
| --- | --- | --- |
| 正式服连接 | 通过正式服插件和本机桥接获取游戏数据。 | 需启用插件并保持传输码可见。 |
| 无限服独立连接 | 提供独立插件、设置页、协议标识和本地记录隔离。 | 已有实现，当前文档仍标记为待无限服实机验收。 |
| 角色信息卡 | 显示姓名、服务器、等级、职业、可读取的专精、阵营和种族。 | 不可读取的信息保留未知状态。 |
| 游戏状态识别 | 识别在线、战斗、死亡、复活、重载和角色切换等状态。 | 基于插件实际观察，不补造离线期间的事件。 |
| 区域与地图 | 显示角色实际所在地图和区域。 | 浏览世界地图不会改变角色位置来源。 |
| 当前地图坐标 | 显示当前地图上的 X、Y 坐标，插件每秒采样。 | 坐标有传输延迟；地图无效或数据过期时清空，不提供自动寻路。 |
| 桥接自动管理 | 桌面端启动、重试并管理自己的隐藏桥接进程。 | 当前真实采集依赖 Windows 和 Python 3.10+。 |
| 校准与故障提示 | 支持采集位置、格宽、采集间隔设置，以及局部格距恢复。 | 局部恢复失败时仍需手动校准。 |
| 演示与排错 | 提供模拟升级、区域、死亡、复活、战斗事件及协议自检。 | 演示数据与真实记录区分，不能代替实机验收。 |

默认数据传输码为 **64×64 物理像素**。桥接支持最低 100 毫秒采集间隔，并对每帧执行校验。游戏最小化、传输码遮挡、画面停更或缩放模糊都可能造成连接中断。

### 2.3 主动陪伴与免打扰

| 功能 | 当前能力 |
| --- | --- |
| 升级祝贺 | 收到真实等级变化后，按当前人设作出回应。 |
| 区域与地点回应 | 玩家进入新的有效地图、副本或战场时，可触发地图逸闻；无资料时简短欢迎，详见 2.13。 |
| 死亡与复活回应 | 根据对应事件和当前角色风格进行互动。 |
| 装备提升祝贺 | 对符合比较规则的装备候选，称呼玩家并播报祝贺及换装询问。 |
| 非战斗定时互动 | 满足在线、存活、非战斗及语音可用等条件后进行简短互动；独立开关和 1～60 整分钟频率，默认开启、1 分钟。 |
| 事件开关 | 升级、区域、死亡、复活提醒可分别开关。 |
| 静音与战斗免打扰 | 可停止主动游戏回应，并保留数据更新；支持战斗期间免打扰。 |
| 冷却与去重 | 控制提醒间隔，过滤重复、过期及其他角色会话的事件。 |

固定装备询问和定时闲聊直接使用语音合成，不需要额外发起聊天模型请求。普通聊天和游戏事件的人设化回应使用相应聊天流程。

### 2.4 装备采集、比较与确认换装

| 功能 | 当前能力 | 边界 |
| --- | --- | --- |
| 新获得装备识别 | 观察本次登录后新进入随身物品的装备，并进行实例去重。 | “新获得”不等于首领掉落，也可能来自购买、邮件、交易或银行取出。 |
| 装备详细资料 | 读取名称、品质、类型、装等、等级要求、公开属性和完整实例链接。 | 缺失或截断资料有明确标记。 |
| 装备说明保留 | 保留可读取的附魔、插槽、套装、触发和使用效果说明。 | 不推算隐藏触发率，也不据此断言套装效果已激活。 |
| 获取历史 | 本地保留每个游戏版本最近 10 条完整装备获取记录，重启后可查看。 | 同一版本的多个角色共用这 10 条额度。 |
| 当前全身装备 | 同步 19 个穿戴槽位，区分已装备、空槽和未知。 | 完整快照收齐后整体替换，传输期间存在延迟。 |
| 按角色保存穿戴快照 | 按游戏版本、账号标识和角色保存最新完整装备资料。 | 离线时查看的是最后保存状态。 |
| 装备上下文聊天 | 支持围绕当前或最后保存的穿戴资料提问，例如查看腿甲属性。 | 不把获取历史当成当前穿戴。 |
| 新旧装备比较 | 比较候选和目标槽旧装备，考虑当前专精、主属性及公开量化属性。 | 不以单纯装等高低替代收益判断。 |
| 明确提升提示 | 对适配且资料完整的无损属性提升、合适空槽物品发起询问。 | 仍受装备类型、使用条件和游戏状态约束。 |
| 属性取舍提示 | 装等与当前主属性提高、部分副属性下降时，明确列出增加和减少的数值。 | 由玩家决定，不保证伤害或治疗收益提高。 |
| 桌面换装询问 | 显示语音或文字气泡及“好／不用”选项。 | 点击“好”只引导回游戏确认。 |
| 游戏内确认换装 | 玩家在游戏内点击确认后，再核验物品实例、槽位和可操作状态并执行。 | 战斗、死亡、锁定及原生绑定确认等限制仍有效。 |
| 换装结果展示 | 接收并展示成功、取消、失败或过期等结果。 | 不把桌面对话中的“同意”当作游戏内确认。 |
| 背包装备复查 | 通过 `/wowc equip check`，或指定物品 ID，重新检查背包候选。 | 无限服前缀为 `/wowf`；复查不伪造新的获取历史。 |

复杂特效、套装、插槽、附魔、未知属性和复杂武器布局仍需要人工判断。当前没有完整的角色输出模拟、自动最优配装或自动战斗系统。

### 2.6 本地魔兽知识库

已实现并接入聊天的能力包括：

- 按正式服、无限服、怀旧服和通用知识分别管理内容。
- 理解部分职业缩写、社区用语、译法和梗。
- 根据当前问题、游戏版本和语言检索相关条目。
- 用户明确指定版本时，优先采用该版本。
- 为条目保存来源、证据类型、适用范围与核对日期。
- 将检索内容临时提供给普通聊天和游戏事件回应。

当前以本地别名和标签匹配为主，不需要向量数据库或额外模型请求。专属社区内容主要覆盖中文和英文。它不是实时补丁数据库，也不意味着已经具备完整的当前赛季攻略。

**状态：已实现。2.20.0 已补上“截图进入当前对话”的链路；真实游戏画面、模型回答仍需端到端验收。**

| 功能 | 当前能力与边界 |
| --- | --- |
| 文字／语音触发 | 支持 `/look` 加问题，以及“看看这个”“看看我的装备”“帮我看看”等自然说法；语音复用现有识别结果。 |
| 游戏窗口截图 | 截取经过身份核验的魔兽世界窗口，支持版本选择；多窗口歧义、最小化、黑屏等情况返回提示。 |
| 当轮图片输入 | 支持图片的聊天模型接收截图；纯文本模型在视觉“用于聊天”开启时复用已有视觉描述，避免重复调用视觉服务。 |
| 已上传图片优先 | 当前消息已有图片附件时，优先使用附件，不再另截游戏画面。 |

使用前开启“设置 → 游戏截图辅助”，配置当前角色的视觉服务及模型，并在游戏中打开希望查看的面板。画面会发送给配置的相关模型服务。

本功能每次请求观察一帧；玩家移动或换视角后，可再次提问。单张截图不能证明隐藏路线、碰撞、任务相位或未出现的 NPC 位置，也不自动控制角色移动。定时截图闲聊是另一个独立开关，见 2.12。

### 2.30 正式服只读查询

**状态：本地源码和定向验证已实现，包含真实 Python／Node／SQLite 链路验证；最终构建与检查以开发验证记录为准。未进行个人模型、语音或真实游戏全链路验收。**

- 支持物品 `item`、底层地图 `map`、世界地图 `uimap`、地区 `area`、技能／法术 `spell`、副本首领 `encounter` 六类的 `search`、`fetch` 和 `stats`。副本自身通过底层地图类型表达，正式服配方尚未整理。

- 只读模式不加载屏幕采集或窗口发现，不读取／创建采集配置，不触发模型或语音。父进程关闭 stdin 时退出，只管理自己启动的查询子进程。
- 数据库以只读不可变连接打开，使用固定白名单 SQL 与参数化条件，不创建表、索引、WAL／SHM，不修改游戏文件或原 SQLite。查询有时间、分页、文本与响应大小上限。
- 来源固定为“正式服本地 DB2”，保留 `wow` 产品、构建、语言、真实导出日期、相关表及数据集标识；本机路径和 `gameRoot` 不进入模型结果，也不编造外站网页链接。
- 未叠加热修、加密分段、原始法术模板、缺失字段和截断资料明确标记。SQL NULL 不补零，空结果只表示当前客户端快照没有匹配，不能据此断言服务器或完整游戏不存在该记录。
- 选错或无效数据库不会覆盖上次有效配置；清除选择会停止自己的只读子进程。换库、清除或关闭期间的迟到查询不能混入新数据源。

- 仅缓存白名单只读工具且来源构建可验证的成功资料；未知来源、错误响应、写入及其他工具不缓存，不能将缓存机制理解为所有 MCP 调用都会复用旧结果。

### 4.8 建议的统一数据流程

为防止两个版本互相污染，建议未来按以下顺序组织查询：

1. 确认问题对应的游戏版本，用户明确指定时覆盖当前角色的默认版本。
2. 选择数据源：无限服用无限图鉴，正式服用匹配构建的本地数据库及适用攻略来源，怀旧服另建分支适配。
3. 以“版本 + 实体类型 + ID”关联记录。需要个性化判断时，再读取有效的角色状态。
4. 返回名称、来源链接、数据版本、采集时间以及临时／缺失标记。
5. 玩家资料不完整时先提供通用资料，不编造任务进度、已学配方、可用交通或当前天赋。
6. 动态价格采用短期缓存，静态资料按构建版本缓存；模型只在需要解释或组织语言时参与。
