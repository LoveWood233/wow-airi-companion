## 一、产品定位

魔兽陪伴精灵是一款围绕《魔兽世界》游玩过程提供陪伴和辅助的 Windows 桌面应用。它以桌面角色为入口，结合玩家的角色状态、装备、金币和游戏事件，提供聊天、语音回应、信息查询与工具服务。

当前产品由三个主要部分组成：

| 组成 | 职责 |
| --- | --- |
| 游戏插件 | 读取公开角色信息，在游戏画面显示数据传输码，并提供游戏内换装确认。 |
| 本机桥接 | 读取传输码，校验、重组数据，向桌面端提供角色状态与事件。 |
| 桌面精灵 | 展示角色、进行对话与语音互动、保存记录，并提供插件中心、快捷启动和截图辅助。 |

## 二、当前已实现的功能

### 2.1 桌面角色与对话陪伴

| 功能 | 当前能力 | 使用条件或边界 |
| --- | --- | --- |
| 桌面角色展示 | 复用 AIRI 的角色形象、桌面窗口、角色菜单和配置能力。 | 实际形象由当前选择和导入的模型决定。 |
| 文字聊天 | 与当前角色进行对话，沿用所选角色卡和系统提示词。 | 需要配置聊天服务和模型。 |
| 语音回复 | 通过配置的语音服务朗读回复。 | 需要可用的语音模型、音色和服务凭据。 |
| 语音输入 | 使用已有语音识别能力，将说话内容送入对话流程。 | 需要配置识别服务及麦克风权限。 |
| 角色风格定制 | 通过角色卡调整说话方式、人设和互动语气。 | 人设与实际音色分别配置。 |
| 使用玩家角色名称呼 | 根据有效的实时角色数据更新称呼，切换角色后同步变化。 | 数据失效时使用中性称呼，演示角色不会覆盖真实角色。 |
| 语音字幕气泡 | 在桌面角色旁显示正在播放的语音字幕。 | 普通播报结束约 3 秒后隐藏，装备询问采用独立的选择计时。 |

### 2.2 游戏连接与角色信息

| 功能 | 当前能力 | 使用条件或边界 |
| --- | --- | --- |
| 正式服连接 | 通过正式服插件和本机桥接获取游戏数据。 | 需启用插件并保持传输码可见。 |
| 无限服独立连接 | 提供独立插件、设置页、协议标识和本地记录隔离。 | 已有实现，当前文档仍标记为待无限服实机验收。 |
| 角色信息卡 | 显示姓名、服务器、等级、职业、可读取的专精、阵营和种族。 | 不可读取的信息保留未知状态。 |
| 游戏状态识别 | 识别在线、战斗、死亡、复活、重载和角色切换等状态。 | 基于插件实际观察，不补造离线期间的事件。 |
| 区域与地图 | 显示角色实际所在地图和区域。 | 浏览世界地图不会改变角色位置来源。 |
| 当前地图坐标 | 显示当前地图上的 X、Y 坐标，插件每秒采样。 | 坐标有传输延迟；地图无效或数据过期时清空，不提供自动寻路。 |
| 桥接自动管理 | 桌面端启动、重试并管理自己的隐藏桥接进程。 | 当前真实采集依赖 Windows 和 Python 3.10+。 |
| 校准与故障提示 | 支持采集位置、格宽、采集间隔设置，以及局部格距恢复。 | 局部恢复失败时仍需手动校准。 |
| 演示与排错 | 提供模拟升级、区域、死亡、复活、战斗事件及协议自检。 | 演示数据与真实记录区分，不能代替实机验收。 |

默认数据传输码为 **64×64 物理像素**。桥接支持最低 100 毫秒采集间隔，并对每帧执行校验。游戏最小化、传输码遮挡、画面停更或缩放模糊都可能造成连接中断。

### 2.3 主动陪伴与免打扰

| 功能 | 当前能力 |
| --- | --- |
| 升级祝贺 | 收到真实等级变化后，按当前人设作出回应。 |
| 区域与地点回应 | 玩家进入新的有效地图、副本或战场时，可触发地图逸闻；无资料时简短欢迎，详见 2.13。 |
| 死亡与复活回应 | 根据对应事件和当前角色风格进行互动。 |
| 装备提升祝贺 | 对符合比较规则的装备候选，称呼玩家并播报祝贺及换装询问。 |
| 非战斗定时互动 | 满足在线、存活、非战斗及语音可用等条件后进行简短互动；独立开关和 1～60 整分钟频率，默认开启、1 分钟。 |
| 事件开关 | 升级、区域、死亡、复活提醒可分别开关。 |
| 静音与战斗免打扰 | 可停止主动游戏回应，并保留数据更新；支持战斗期间免打扰。 |
| 冷却与去重 | 控制提醒间隔，过滤重复、过期及其他角色会话的事件。 |
| 播报优先级 | 定时闲聊等待已有聊天和装备询问，离线期间不会积累多次闲聊。 |

固定装备询问和定时闲聊直接使用语音合成，不需要额外发起聊天模型请求。普通聊天和游戏事件的人设化回应使用相应聊天流程。

### 2.4 装备采集、比较与确认换装

| 功能 | 当前能力 | 边界 |
| --- | --- | --- |
| 新获得装备识别 | 观察本次登录后新进入随身物品的装备，并进行实例去重。 | “新获得”不等于首领掉落，也可能来自购买、邮件、交易或银行取出。 |
| 装备详细资料 | 读取名称、品质、类型、装等、等级要求、公开属性和完整实例链接。 | 缺失或截断资料有明确标记。 |
| 装备说明保留 | 保留可读取的附魔、插槽、套装、触发和使用效果说明。 | 不推算隐藏触发率，也不据此断言套装效果已激活。 |
| 获取历史 | 本地保留每个游戏版本最近 10 条完整装备获取记录，重启后可查看。 | 同一版本的多个角色共用这 10 条额度。 |
| 当前全身装备 | 同步 19 个穿戴槽位，区分已装备、空槽和未知。 | 完整快照收齐后整体替换，传输期间存在延迟。 |
| 按角色保存穿戴快照 | 按游戏版本、账号标识和角色保存最新完整装备资料。 | 离线时查看的是最后保存状态。 |
| 装备上下文聊天 | 支持围绕当前或最后保存的穿戴资料提问，例如查看腿甲属性。 | 不把获取历史当成当前穿戴。 |
| 新旧装备比较 | 比较候选和目标槽旧装备，考虑当前专精、主属性及公开量化属性。 | 不以单纯装等高低替代收益判断。 |
| 明确提升提示 | 对适配且资料完整的无损属性提升、合适空槽物品发起询问。 | 仍受装备类型、使用条件和游戏状态约束。 |
| 属性取舍提示 | 装等与当前主属性提高、部分副属性下降时，明确列出增加和减少的数值。 | 由玩家决定，不保证伤害或治疗收益提高。 |
| 桌面换装询问 | 显示语音或文字气泡及“好／不用”选项。 | 点击“好”只引导回游戏确认。 |
| 游戏内确认换装 | 玩家在游戏内点击确认后，再核验物品实例、槽位和可操作状态并执行。 | 战斗、死亡、锁定及原生绑定确认等限制仍有效。 |
| 换装结果展示 | 接收并展示成功、取消、失败或过期等结果。 | 不把桌面对话中的“同意”当作游戏内确认。 |
| 背包装备复查 | 通过 `/wowc equip check`，或指定物品 ID，重新检查背包候选。 | 无限服前缀为 `/wowf`；复查不伪造新的获取历史。 |

复杂特效、套装、插槽、附魔、未知属性和复杂武器布局仍需要人工判断。当前没有完整的角色输出模拟、自动最优配装或自动战斗系统。

### 2.5 金币账本与成长记录

| 功能 | 当前能力 | 统计口径 |
| --- | --- | --- |
| 角色钱包余额 | 记录已观察角色的金币余额，以金、银、铜显示。 | 未登录或未观察角色不会自动补齐。 |
| 累计收入与支出 | 分别记录角色钱包流入、流出及净变化。 | 首次余额只建立基线，不计为收入。 |
| 账号维度汇总 | 按插件本地生成的账号标识汇总多个角色，并支持备注。 | 不读取战网邮箱或真实账户身份。 |
| 桌面离线后的累计补入 | 插件持续记录且计数未丢失时，重连可合并未入账的累计差额。 | 不能恢复插件未观察或未保存的变化。 |
| 等级历史 | 按角色保存等级变化与每级耗时。 | 采用现实时间，包含离线时段。 |
| 不完整记录标记 | 对首次接入、缺失升级过程和未知时间作区分。 | 不将推测时间展示为精确升级耗时。 |

金币账本统计的是**钱包资金流动**。邮件、转账和银行存取也会影响数字；当前不提供完整利润核算、逐笔交易归因或银行总资产统计。

### 2.6 本地魔兽知识库

已实现并接入聊天的能力包括：

- 按正式服、无限服、怀旧服和通用知识分别管理内容。
- 理解部分职业缩写、社区用语、译法和梗。
- 根据当前问题、游戏版本和语言检索相关条目。
- 用户明确指定版本时，优先采用该版本。
- 为条目保存来源、证据类型、适用范围与核对日期。
- 将检索内容临时提供给普通聊天和游戏事件回应。

当前以本地别名和标签匹配为主，不需要向量数据库或额外模型请求。专属社区内容主要覆盖中文和英文。它不是实时补丁数据库，也不意味着已经具备完整的当前赛季攻略。

### 2.7 自然语言截图与看图对话

**状态：已实现。2.20.0 已补上“截图进入当前对话”的链路；真实游戏画面、模型回答仍需端到端验收。**

| 功能 | 当前能力与边界 |
| --- | --- |
| 文字／语音触发 | 支持 `/look` 加问题，以及“看看这个”“看看我的装备”“帮我看看”等自然说法；语音复用现有识别结果。 |
| 游戏窗口截图 | 截取经过身份核验的魔兽世界窗口，支持版本选择；多窗口歧义、最小化、黑屏等情况返回提示。 |
| 当轮图片输入 | 支持图片的聊天模型接收截图；纯文本模型在视觉“用于聊天”开启时复用已有视觉描述，避免重复调用视觉服务。 |
| 已上传图片优先 | 当前消息已有图片附件时，优先使用附件，不再另截游戏画面。 |
| 临时上下文 | 自动截图只用于当前请求，不写入本地聊天历史；下一轮或历史重试不复用旧截图。 |
| 保守意图识别 | 否定截图、引用／翻译示例句，以及查看代码或文档等请求不触发游戏截图。 |
| 看图求助 | 根据可见地形、入口、任务文字、地图标记、NPC 和已打开的装备面板提供分析。 |

使用前开启“设置 → 游戏截图辅助”，配置当前角色的视觉服务及模型，并在游戏中打开希望查看的面板。画面会发送给配置的相关模型服务。

本功能每次请求观察一帧；玩家移动或换视角后，可再次提问。单张截图不能证明隐藏路线、碰撞、任务相位或未出现的 NPC 位置，也不自动控制角色移动。定时截图闲聊是另一个独立开关，见 2.12。

### 2.9 游戏快捷启动

**状态：代码和入口已实现，已有本地可执行文件检查记录，实际启动及登录流程仍需实机验收。**

- 配置战网、正式服、无限服和怀旧服启动路径。
- 设置默认目标，从桌面角色工具栏快速启动。
- 未配置时进入设置页面。
- 启动前核对可执行文件签名、产品身份和安装版本。

启动成功只表示进程创建成功，不表示已登录、已完成更新或已进入角色。

### 2.10 多语言与本地配置

- 桌面界面支持英文、简体中文、繁体中文、西班牙语、法语、意大利语、葡萄牙语、日语、韩语、俄语、泰语和越南语。
- 游戏插件按客户端语言显示提示，桌面语言独立选择。
- 当前角色名、装备名、聊天历史和用户提示词保留原文。
- 启动脚本默认使用 `%USERPROFILE%\.airi-wow-companion` 保存配置与角色记录。
- 正常模式和开发模式共用该资料目录，减少配置分流。
- 提供启动、安装、日志和桥接排错入口。

部分高级设置译文仍需母语审校；界面语言支持不代表每个语音服务都支持相同语言。

### 2.11 已有独立组件：攻略情报接口

工作区中的 `WoWIntelAPI` 已提供独立 HTTP 服务，可查询正式服资讯、职业与专精攻略入口，以及攻略简介和章节索引。

当前代码支持的来源是 Wowhead，内容主要为英文。该模块保留来源链接及缓存状态，但**本次未找到它已接入桌面聊天的证据**，因此单列为可复用组件。

它不生成完整天赋导入码，不复制整篇攻略，也不直接给出针对玩家装备的最优配装结论。上游内容当前是否可访问，本次未作联网验证。

### 2.12 定时截图与风景闲聊

**状态：已实现，已有专项测试、桌面类型检查和构建通过记录；实际模型与游戏画面效果待验收。**

- 在“设置 → 闲聊设置”分别控制普通闲聊和截图闲聊，两者均支持 **1～60 整分钟**的滑条设置。
- 普通闲聊默认开启、1 分钟；截图闲聊默认关闭、10 分钟。
- 截图滑条的 **1～5 分钟为红色**，选中时提示模型额度消耗可能更快；**6～60 分钟为绿色**。
- 开启后定时截取魔兽世界窗口，由视觉模型描述风景，再由聊天模型按当前人设生成简短互动并朗读，配合字幕。
- 需要视觉、聊天和语音服务及音色。原图不写入文件或本地聊天历史。
- 战斗、离线、切换角色／对话、模型变更和关闭功能会停止未完成的截图互动；聊天与游戏提醒优先，不补发积累的多次闲聊。

### 2.13 地图、副本与战场逸闻

**状态：已实现，2.19.0 已接入桌面和插件。**

- 切换地图、进入副本或战场后，地点稳定 **3 秒**，用当前角色语气讲 **2～3 句**相关逸闻，并称呼最新登录的玩家角色名。
- “设置 → 闲聊设置 → 地图逸闻”可独立开关，默认开启；同时需启用对应游戏版本的区域变化提醒。
- 内置 **24 个**有官方资料来源的地点，覆盖野外、城市、副本和战场；使用本地资料，无需截图或调用视觉服务。
- 连续切图只讲最终地点，同一副本换楼层不重复；战斗或对话忙碌时暂缓，待发最长 120 秒。
- 两次逸闻至少间隔 60 秒，同一地点 10 分钟内不重复。
- 未收录地点仅简短欢迎，不编造历史；当前地点资料库不为无限服匹配历史条目。

逸闻属于历史背景，不用于判断当前 NPC 是否存在、任务阶段、路线是否可走或副本机制是否改变。

### 2.14 游戏日历、私人日程与副本重置提醒

**状态：已实现；相关测试、桌面构建和设置页回归已有通过记录，真实日历加载与语音播报待验收。**

| 提醒类型 | 当前行为 |
| --- | --- |
| 官方节日、奖励周、PvP 活动 | 开始当天首次登录时提示；明确结束时间的前一天提醒“明天几点结束”。 |
| 私人、公会、社区日程 | 开始当天提醒；存在明确结束时间的跨日日程，在结束前一天提醒；已拒绝或退出的邀请排除。 |
| 副本锁定重置 | 重置前一天及当天提醒，包含副本名称、难度和具体时间。 |
| 合并播报 | 同一次首次登录读取到的多个事项合并成摘要，遵循当前人设和语音流程。 |
| 日期与时间 | 采用游戏服务器日历日期和实际时间，不把“前一天”当作固定提前 24 小时。 |
| 重复提醒控制 | 官方活动按游戏、账号、服务器、日期和事件去重；私人日程与副本进度进一步按角色去重。 |
| 暂缓条件 | 战斗、死亡、静音、缺少聊天模型或对话忙碌时延后提交。 |

这是**每日首次登录摘要**，不是持续在线时到点响铃。没有结束时间的日程不会推测结束时间。去重保存的是提交尝试，提交失败不自动重试，也不保证玩家已实际听到声音。

私人日程扩展已更新本机正式服文件；先前生成的正式服 2.14.0／无限服 1.11.0 ZIP 不一定包含该后续扩展，部署时应核对源码与安装文件。

### 2.15 组队入本与战场的增益缺失提醒

**状态：已实现。插件、桥接和语音流程测试通过，实际游戏增益读取和扬声器播报待验收。**

当前实现范围：

- 在组队状态下进入副本或战场后，检查队友是否缺少玩家当前角色能施放且已学会的队伍增益。
- 例如玩家是战士，队友缺少“战斗怒吼”时，由陪伴精灵语音提醒补上。
- 逐个检查可读取的队友；离线、距离过远或接口限制导致无法读取时，不直接判定缺失。
- 进入后等待加载，同次进入限制重复提醒；战斗中延后检查，复用现有数据传输码和语音通道。

支持战斗怒吼、奥术智慧、真言术：韧、野性印记、天怒和青铜龙的祝福。需要客户端提供现代增益和法术书接口。此项只提醒，不自动施法。详见 [发布验证记录](verification-group-buffs-publish-2026-10-29.md)。

### 2.16 聊天生成宏与游戏内导入

当前数据范围以固定来源版本的正式服传送门为主，不涵盖完整的船、飞艇、飞行点、步行路网或随身传送技能。目的节点坐标不一定是实际落点，且尚未读取当前角色解锁条件，不能直接保证“这个角色现在能用这扇门”。

## 五、建议推进顺序

1. **先完成现有功能的真实验收。** 优先处理无限服、CurseForge 插件中心、截图问答、宏导入、日历播报和快捷启动；验收队伍增益提醒，核对发布产物与源码是否一致。
