# 魔兽陪玩 · 114 段牧师动作整合方案

八职业当前交接规则见[动作接缝、尾帧结算与独立语音](motion-seams-and-settlement.md)。

八职业模拟测试采用仓库中八个职业都有的 **96 个动作**。牧师有完整 114 段，其余七个职业各缺相同的 18 段。[八职业对照与模拟验收](eight-class-common-96.md) · [96 项触发索引及 18 项缺口](eight-class-common-96.json)

以下保留 2026-11-19 版牧师 114 段动作的设计基线。游戏状态决定何时可以提醒，玩家决定点哪个节目；只有前两者都安静下来，精灵才自行换姿势。开口与动作分别判断，玩家不必等一段十秒的影片播完才看到答案。

本次提交提供替换方案、逐项索引、调度规格和独立的规则参考函数。媒体交付与 AIRI 客户端接线留到实施阶段。协作方可先用本文评审范围和数据，再按用例验收实机表现。

| 评审问题 | 从哪里看 |
| --- | --- |
| 这 114 个动作各在何时出现，播哪一段，能说什么 | [互动—动画索引](interaction-animation-index.json) 的 `actions`。按 `id`、原中文 `clip_key` 或场景检索 |
| 拖动时突然低血、死后很快复活、讲故事时被叫停，由谁接管 | [互动调度及回放用例](interaction-logic.md) |
| 如何重放候选选择、低血的声音和字幕、钱袋分档 | [纯函数参考实现](interaction-policy.mjs)。仅消费调用方提供的数据，可离线运行 |

## 哪些画面要换

比对基线为同事仓库的 [main 快照 8ae020e](https://github.com/LoveWood233/wow-airi-companion/tree/8ae020ede01f3587d9676d39b2bd151a7c336121)。[内置清单](../../airi/apps/stage-tamagotchi/src/renderer/public/dsh-pet/builtin/pack.json) 已有 114 个 WebM 文件名，去掉后缀后，与[新版牧师母版](https://github.com/LoveWood233/wow-airi-companion/tree/8ae020ede01f3587d9676d39b2bd151a7c336121/assets/video/牧师全动作-20261119)的 114 个动作名逐项相同。每一行索引记录源 MP4 的 Git 对象标识，便于核对同名文件究竟来自哪一版。

| 上游对象 | 交付约定 |
| --- | --- |
| 114 段新版母片 | `<clip_key>_00001.mp4` 是制作输入。源片均为 640×360、24 fps、无音轨、无透明通道。示例 A017 的母片为 `吃饭·碗饭_00001.mp4` |
| AIRI 动作包 | 114 段全部从新版母片制作，发布名为 `<clip_key>.webm`，如 `吃饭·碗饭.webm`。保留原字形、标点和大小写。透明边缘、循环衔接和朝向在真实舞台复核 |
| 随机、选择与查找 | 编号 A001–A114 供团队沟通，`clip_key` 供播放器查文件，`route` 标识触发原因。A006 的升级与首领胜利可播放同一画面，各用自己的语音条件 |
| 旧八职业资产包 | 该系列含额外表情。新版魔兽模式的所有选片、补位和随机选择都限定在这 114 个键内；选片失败回到健康的新版呼吸片，或保留静帧 |

[动画包 v1 契约](../../airi/apps/stage-tamagotchi/src/shared/dsh-pet.ts) 校验声明过的 WebM 文件和分组引用。继续沿用 `idle`、`turn`、`drag`、`clicks`、`categories`、`events`、`moves`、`sleep`、`baifan`。触发条件单独放在互动索引，保留三段睡眠和既有朝向限制。制作时根据实片标注可循环区段与允许镜像的段，避免将读得出的文字左右翻转。

## 三个入口共用一个舞台

| 主入口 | 动作数 | 一次实际体验 |
| --- | ---: | --- |
| 游戏内信息 | 7 | 此场第一次有效低血用 A002 提醒，随后死亡则改 A007。复活可用 A001 行礼，整个死亡到复活过程最多说一句安慰 |
| 主动互动 | 71 | 玩家点名「小提琴演奏」就播 A035。点「看钱袋」先核对当前角色与金额。A074/A075 只在查询确实耗时后出现，答案到达即可交付 |
| 待机 | 36 | 呼吸和张望可陪长战斗，安全久候才开放消遣。27 段同时允许玩家从菜单点播。手动点中秋节目无需开启中秋主题，自动出现时仍看主题与频控 |

27 个菜单旁路已写入相关动作的 `secondary_route`。另有两项条件复用写在 `cross_routes`，不增加动作数。A006 的首领欢呼需要首领身份、本人参与、击败结果、安全状态和主动许可；A073 的故事动作只在玩家同意、内容适用于当前进度且首段获准时启动。现有事件不提供可信的首领击败结果，仅有敌人名字、丢失目标或脱战都应安静。故事正文、字幕和主动问候遵循玩家的明确偏好。

## 在同事代码里从哪儿接

魔兽陪玩模式统一使用这 114 段。菜单、手势、问答和待机在正式服和无限服共用。游戏事件按当前版本选择适配器，分别保存角色、事件游标和冷却。下表以无限服为首轮联调对象。正式服按 WCP1 实际上报的事件启用同一套路由，缺少对应信号时保持安静。

## 实施和撤回

1. **制作与验证整包。** 从固定基线取原片，按索引的 Git 对象标识核对全部 114 段。对无透明通道的 MP4 做遮罩和边缘处理，导出真实带透明效果的 WebM。用运行器实际解码每段。在深浅两种背景、翻面、拖动和睡眠循环中确认摆位和轮廓。按导入器限制检查每段 ≤32 MiB、整包 ≤512 MiB。记录发布版本与成品文件校验值，供识别新版画面。
2. **接通输入与独占播放。** 先在回放中接 7 个游戏反馈、呼吸、张望和手势，再接点播、钱袋、喂饭、小睡和主动话题。调度器提交前先复核身份和时效。画面实际起播才扣画面配额，声音实际开口才扣声音配额。
3. **在无限服试用。** 同时核对当前模式、素材版本和 114 项清单后，一次切换媒体与新规则。测试已有老内置包、用户自定义包和全新安装这三种状态。魔兽陪玩模式明确选择新版牧师包，并记录先前选包供退出该模式时恢复。任一片缺失或版本不符时不激活部分升级。
4. **保留撤回路径。** 发布切换之前保存原先选包与交互策略版本。验证失败时，按整套版本同时撤回，清空候选、旧语音和未完成加载。不能让新版互动在回退后继续引用另一版素材。

## 通过条件

- **本次评审**应能由同事独立复核 114 个唯一原名、114 个原片 Git 对象标识、7/71/36 个主入口、27 个菜单旁路，以及条件复用与钱袋六档。PR 的差异只应列出本目录的文本文件。
- **接入验收**应覆盖[互动规格里的回放](interaction-logic.md#降级与回放)，再采集一次真实无限服从进战、低血、死亡、复活到安全拾取的时间线。分别留存原事件、选择原因、首帧、字幕和实际起声。尚缺首领或剧情依据时，验收其静默路径。
- **素材验收**要求正式舞台确实播放新版 114 段，影片逐段可达，战斗中没有节庆、进食等高干扰演出。变更前后同名，故须比对成品指纹或实际抽帧；仅通过文件名检查不足以判定替换成功。
