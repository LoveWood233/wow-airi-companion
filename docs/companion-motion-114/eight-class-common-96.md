# 八职业共有动作与模拟验收

在仓库版本 `34e62b6`，牧师有 114 段正式动作。战士、圣骑士、猎人、盗贼、德鲁伊、法师、术士各有 96 段，这七套的动作名完全相同。八职业共有的 96 项对应 **768 段职业原片**，每个动作都能从八个职业自己的目录中各取一段。牧师其余 18 段继续保留原编号。本轮模拟只选择这 96 项。[固定版本的职业目录](https://github.com/LoveWood233/wow-airi-companion/tree/34e62b692242b980f1ec173a01cac264318c5fd3/assets/video)

| 触发入口 | 原 114 项 | 八职业共有 | 七职业缺少 |
| --- | ---: | ---: | ---: |
| 游戏内信息 | 7 | 7 | 0 |
| 主动互动 | 71 | 56 | 15 |
| 待机 | 36 | 33 | 3 |
| 合计 | 114 | 96 | 18 |

共有待机动作中，24 项保留手动点播入口，已计入 33 项待机。A006 仍可在确认首领胜利后复用，A073 仍可在玩家同意且首段内容获准后用于故事，二者沿用原表的触发条件。

## 从触发到各职业的影片

[八职业索引](eight-class-common-96.json) 的 `actions` 列出实有的 96 项，`priest_only` 列出 18 项差集。每条记录以原 A 编号关联[完整互动表](interaction-animation-index.json)的条件、优先级、取消规则和语音。客户端原有的包内分组描述素材用途；本测试按互动表的 `entry`、`route` 和可选 `secondary_route` 解释输入。同一个 A 编号在不同职业使用同一个触发含义。

1. 先将当前事件、手势或待机状态交给[互动调度规则](interaction-logic.md)，同时把候选限制为共有 96 项。记录输入、被选中的 A 编号与原因。比如同场低血降至 19% 且提醒有效时可命中 A002。若拖动已捕获，则保持跟手，释放后重验状态。
2. 对每个职业，用其 `class_directories` 对应的目录及准确的 `clip_key` 拼出 `assets/video/<职业>/<clip_key>_00001.mp4`。例如 A002 的战士和法师区域分别读取 `assets/video/战士/被吓一跳_00001.mp4` 与 `assets/video/法师/被吓一跳_00001.mp4`。数字后缀和中间标点保留原样。
3. 八个区域收到同一次已通过的触发后，各自显示本职业影片。任一区域缺文件、校验失败或解码失败，该区域必须记录失败。制作模拟录像时允许使用可控时钟推进等待、脱战和冷却，验收记录需区别模拟时钟与录像播放时长。

## 运行连续触发测试

在仓库根目录执行以下命令。测试只需 Node.js，本地没有视频也可以复核选片与拒绝结果。

```sh
node docs/companion-motion-114/tests/replay-common-96.mjs
```

传入 `--out <已存在的目录>` 可保存原始输入、命中时间线和边界断言。一次会话依次处理 139 次输入，产生 96 次选片，其余 43 次只改变状态或保持当前画面。覆盖以主入口计数。实际回放中，23 个待机动作经玩家点播触发，其余 10 个使用待机路由。另行运行的 26 项边界断言覆盖拖动中低血、释放后读数不足、同场去重、死亡后复活、首领与升级合并、查询等待、安静指令和缺项拒绝等情形。

同屏录像的八格共用一个会话，左上开始依次为战士、圣骑士、猎人、盗贼，第二行为牧师、德鲁伊、法师、术士。每条原始输入送到同一个 `Replay.step()` 实例，根据返回结果选片。未命中时保留正在播放的动作。界面上的 `INPUT` 是最近一次输入，`HOLD` 表示该输入没有触发换片。片段按原始帧率播放。测试推进虚拟时钟以覆盖冷却和安全等待，右上角记录连续录像时长，底部显示本次动作命中的模拟时刻。

### 本次录像实测

成片为一条 1536 × 864 的 H.264 视频，24 fps，共 22,659 帧，时长 15 分 44.125 秒。连续解码至末帧，各帧显示时间戳均相差 1/24 秒。对 768 段源视频逐一核对 Git 对象并完整解码，分别比较成片中 96 次选片 × 8 个区域的中帧与独立解码的对应原片，中帧全部匹配到正确职业。额外检查了各格首、中、尾共 2,304 处画面。录像文件为 187,439,202 字节，SHA-256 为 `328e16adcf095b132d0eef0a5ef23ac75e792f15c7c277fbda2780ee969d41c9`。

## 如何复核覆盖范围

从 `source.commit` 的 `assets/video` 对八个职业目录的直接子文件取清单，只计算匹配上述片名的 MP4。预览 PNG 和嵌套试样目录另存用途。逐项去除准确后缀 `_00001.mp4` 后求交集，再按 `clip_key` 关联 114 表。八个目录的 Git 树标识已保存在索引的 `class_tree_sha`。七套非牧师素材的键集合均等于交集，牧师目录 114 个正式 MP4 的 Git blob 标识与原表 `source_git_blob` 逐项相同。共有项中，每行在八个职业目录对应八个不同的 MP4 blob。

同事可从仓库根目录用以下命令复核某一角色或两个同名片的对象标识；同样的方法适用于索引的每一行。

```sh
git rev-parse 34e62b6:assets/video/战士
git rev-parse '34e62b6:assets/video/战士/被吓一跳_00001.mp4'
git rev-parse '34e62b6:assets/video/法师/被吓一跳_00001.mp4'
```

| 层次 | 通过条件 |
| --- | --- |
| 索引 | 96 个唯一 A 编号继承原路由，768 条职业文件路径存在。18 个差集编号均仅牧师具备，且不会进入八职业共同池。 |
| 规则 | 模拟合法事件应产出预期 A 编号。对时间边界、跨角色旧事件、重复事件、拖动占用、静默和缺片分别检查抑制或取消原因。不得由画面倒推触发成功。 |
| 一镜到底的模拟录像 | 八个职业固定在同一画面的八个区域，使用一个连续时间轴。观察者能看出输入、预期动作与职业身份。逐项核对 96 次动作覆盖及各职业取片，保留未通过的情况。 |
| 客户端接入 | 安装包运行时的职业识别、包选择、真实游戏信号、语音起声、透明合成与渲染时延均需另行在目标客户端验证。 |

仓库的[职业素材说明](../../assets/video/README.md)按每职业 114 项描述完整包。当前七个 96 项目录能参加上述共同触发测试。若接入桌面发行版，还需评审完整性门槛、缺项在产品菜单中的呈现以及职业切换时的加载策略。
