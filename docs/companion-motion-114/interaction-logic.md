# 大肥鱼如何选下一段动作

以下是生成既有覆盖录像时的调度基线。八职业接入现以[尾帧结算与固定窗口](motion-seams-and-settlement.md)为准，新规则替代本文的片中抢播、滚动预算及因视觉冲突而丢弃已获准语音的条款。

这是供 AIRI 桌面端实施和回放的交互规格。动作集合见同目录 [互动与动画索引](interaction-animation-index.json)。索引编号便于评审，播放器按原中文 `clip_key` 查当前包。同一片段可由不同入口复用，选择入口也决定当次的优先级和可说的话。

## 输入和播放各由谁负责

| 位置 | 后续整合职责 |
| --- | --- |
| WoW 插件、桥接、桌面 WoW store | 继续提供当前游戏版本、角色、桥接会话、快照和事件。适配层将可信变化转换为候选。普通换图更新上下文。断线、身份变化和快照过期使依赖旧事实的候选失效。 |
| 桌面菜单、指针、聊天及已有闲聊计时 | 发送玩家所选条目、指针捕获、提问、获准话题或停止。沿用玩家已有的提醒、静音、字幕和免打扰设置。 |
| 拟增的桌面动作调度器 | 独占正式舞台的选片权。三个入口共用有界候选槽，读取同一份当前状态，决定保留、开始、中断、合并或丢弃，并给出原因。 |
| DSH 舞台和语音出口 | 舞台保留双视频预载、透明绘制和朝向规则。指针、情绪属性及片尾回调均交由调度器决定下一段。语音共用一个出口；文本、声音和动画分别回报实际交付。设置页的预览不占正式舞台，也不写正式冷却。 |

在 `wow-companion.ts` 完成 `acceptState` 后，只有运行中的主窗口（`owner && running`）处理当前游戏适配器的原始事件批次。角色、游标和冷却按游戏版本隔离。沿用现有启用开关、桥接来源与新鲜度检查、角色身份及事件游标，再做 8 秒拾取合并与优先级排序。其他窗口只更新展示。仅消费 `CompanionPolicy.accept` 挑出的单条事实会漏掉同批事件。现有 `react()` 中送 `queueFixedNotice` 的通知也纳入同一语音出口，避免旧拾取播报或重复的死亡安慰。

一次候选记录来源事件号、角色与会话、源事件时刻、接收时刻、失效时刻、入口、路由、依赖的状态和当次优先级；按需附战斗号、死亡过程号、问答轮次或手势号。桥接缺少原生编号时，由适配层按同身份连续观察到的状态边沿生成。原始信号不足以区分两次事件时只更新快照。角色换线、重连或切换游戏版本后，先建立当前基线。

## 如何仲裁

同一批输入**先更新完状态，再做一次选择**。这样同一帧内死亡和低血的结果不依赖回调顺序。

| 先后 | 候选 | 开始或取消的条件 |
| --- | --- | --- |
| 控制 | 暂停、停止、捕获及释放、唤醒 | 暂停冻结画面和本地专属状态时钟，恢复时检查新快照与事件有效期。停止立即结束当前节目及其附属声音；清除该交互的待播项。已捕获拖动期间画面跟手。 |
| 1 | 死亡 `death` | 当前角色仍死亡，本次死亡只叹气一次。清掉低血、庆祝和已失效的点播，随后进入安静池。复活撤掉尚未交付的死亡反馈。 |
| 2 | 低血 `low_health` | 角色存活、同一场战斗、事件自身的 healthPercent 严格低于 20%、事件年龄小于 10 秒。普通快照没有持续血量，释放时校验角色、同场、存活和新鲜度；需要松手时或之后的可信读数仍低于 20% 才补播。无读数时等到原警报过期，恢复到 20% 即撤销。每场最多一次提醒，口播和稍后接上的画面共用同一事件号。 |
| 3 | 玩家明确操作 `manual` | UI 在按下时即时反馈。普通点播只留最近一项，通常等到下个片尾，连续点不同节目起播至少相隔 10 秒。请求满 12 秒仍不可播时结束并给界面提示。相同节目正播时不重启。 |
| 4 | 普通游戏 `normal` | 连续脱战满 10 秒后重验，事件年龄小于 30 秒。只保留一项，等级预警、复活、升级、拾取依次优先，同级取最新。重复 ID 合并。相同边界的等级预警在 2 分钟内合并。 |
| 5 | 精灵主动闲聊 `proactive` | 复用现有闲聊资格。默认间隔满 5 分钟、本次累计 5 次脱战且已稳定脱战 10 秒。还需话题有效、允许主动触达且语音空闲。 |
| 6 | 待机 `idle` | 无合格的更高候选时轮换。战斗或死亡只允许呼吸、张望和必要反馈，以及玩家的低干扰手势。 |

下列伪代码描述一次调度。死亡、低血、拖动、停止和唤醒可打断普通片，进战收掉高干扰节目并退出小睡。普通交接遵从实际片尾和预载就绪。

```text
接收同批输入：
  更新身份、生死、战斗、语音、指针和偏好；取消已失效的音画输出
  将索引命中的候选按来源编号去重，合并到有界槽；相同状态的重复快照不建候选
  移除过期、跨角色、旧轮次、事实失效或当前包缺片的候选
  若暂停：返回
  处理停止、捕获和释放；独立评估本次是否可交付字幕或人声
  若仍拖动：维持拖拽画面，返回
  按优先级选取当前可播的最高候选；片尾未到且不能打断时，保留到下一次复核
  预载选中片；就绪时重新检查候选身份、事实、时限及当前播放代次
  候选仍有效才切换前台；实际首帧计一次画面，实际开口计一次声音
  回调只处理当前 playback_id；晚到的 ended/error 不得覆盖新片
```

普通游戏、主动闲聊的画面和待机点缀共用滚动 60 秒最多 2 次的预算。回呼吸、手势与危急反馈另计。8 秒内连续拾取归为一批，升级与拾取撞车优先升级，同批最多一段收纳，拾取静默。等待途中到期、换角或再入战均重新判定。普通动画候选不足时可回呼吸；等待语音候选过期直接放弃。

## 各入口的细节

| 情境 | 状态变化与边界 |
| --- | --- |
| 点击与拖动 | 记录从按下位置的最大位移。松开时位移不超过 6 个 CSS 像素才可轻点；超过 6 即转入捕获拖动。松开、失焦、取消任一信号都释放捕获并消费手势。700 毫秒合并连点，已有点击回应播放中时忽略重复。首次问候优先「点击回应-元气挥手」。点击、摸摸与拖动共用 30 秒人声冷却。 |
| 睡眠与喂饭 | 点小睡依次「睡觉-开始 → 睡觉-循环 → 睡觉-起来」。10 分钟到点、轻点或进战均结束睡眠，严重事件优先，每轮只执行一次唤醒。玩家轻点唤醒的这一手势不再挥手。喂饭只选一次入场，进入「期待开饭」后等玩家选择，饭团和碗饭分别走对应咀嚼段；等待 20 秒无操作或玩家停止即退出。整轮最多一句。 |
| 查钱袋 | 仅玩家明确查询才选档。取同一角色当前可信非负余额 B 和正储蓄目标 G，两者用整数铜币。按顺序检查 B=0 → A070；100B≥100G → A065；100B≥75G → A066；100B≥40G → A067；100B≥15G → A068；其余正余额 → A069。缺目标只返回已知余额，缺余额只提示未读到。 |
| 等回答与讲故事 | 查询背包或角色资料时，实际等待超过 2 秒才允许一个等待动作。首个获准语义段到达即可交付并撤销等待。对话以 turn_id 与 segment_id 标识，一轮最多起一次说话动作。玩家已同意听故事、当前版本与进度适用、内容处在剧透许可范围内，可复用 A073；ST03 是一条可选故事框架。换轮取消旧语音和未交付段。 |
| 已确认首领击败 | 新联动可复用 A006。须同时核实敌对首领身份、玩家参与、成功结果、安全状态与主动许可。与同一战果的升级庆祝合并一次，用获准的胜利正文。仅名称已核实才可称名。只观察到目标消失、普通脱战、无条件击杀数或拾取，均不触发自动首领庆祝。战斗后玩家主动提起该事走当轮问答。 |
| 待机与主题 | 从最近一次可见点缀起抽取 45–75 秒，在自然片尾换动作。在可轮换状态下，最后一个不晚于 90 秒的可用片尾为「东张西望」保底，允许一次普通预算例外。持续呼吸、回呼吸、鼠标路过和新快照不顺延。暂停、拖动、小睡、喂饭等专属状态豁免，退出后重启待机时钟。 |
| 待机多样性 | 用会话随机种子和计数打乱合法候选，去掉最近 3 个点缀。池太小时逐个放开最久的一项，尽量避免相邻重复。安全待机满 3 分钟才放入消遣；消遣、饭点、节庆合计每 3 次点缀最多 1 次，同一节庆动作至少间隔 10 分钟。饭点按玩家本地时段，节庆按已启用主题。手动菜单复用索引指定的 27 项时走 manual，仍受战斗限制。 |

## 语音与动画如何同时交付

- `none` 只动，`nonverbal` 只在有合适录音且允许时发短声，`info` 传已核实事实，`reaction` 用本次事件的角色短句，`reply` 只读本轮已经获准的正文。索引中的音色指示不送入 TTS。普通自动待机零台词，待机轻声默认关闭，开启后仍须安全待机满 5 分钟，相邻两次至少隔 5 分钟。
- 语音出口同时只读一条。低血可打断装饰声音；玩家正在输入语音或听当前问答时只交付允许的字幕和画面。拖着角色时若允许播报，低血声音可以先到，释放后再复核画面，绝不重复同一提醒。静音时照常完成视觉反馈。死亡和复活共用一次情绪台词；相同装饰台词 10 分钟内不重读。
- 连续点播的装饰人声至少相隔 30 秒。同一节目或整轮喂饭最多说一句。有多个台词变体时排除最近两条，候选不足则选最久未用的一条。低优先级声音撞车直接略过。
- 问答内容如联用 DFY 的 FAQ，先做版本、意图、槽位、证据与偏好检查。P0001 的结构化前提通过才选首领语句。P0177 的严格静默允许零正文、零 TTS，不附应答或告别。玩家只关闭主动提醒时保留后续手动问答。FAQ 卡号供可选对接，桌面每次点击和待机都可以在本地完成。
- 影像走独立 `clip_key` 请求，不占用 DFY 试验中业务技能的 `action_id`。记录候选被拒原因、首帧、语义段显示、起声、取消和结束。玩家未回应或多点几次，只记观察；长期偏好以其明确表达为准。

## 降级与回放

普通片到实际时长加 2 秒仍无 ended，或预载、解码失败，释放本次播放锁并将该坏片在本次会话跳过。先回本包健康的呼吸片，基础片也坏时保留可用静态帧，文本和手势继续可用。循环片由所属状态控制退出。离线时清掉游戏候选，保留本地手势和安静待机；连接恢复时建立新基线，不重放断线期间事件。

以下用例应在接入实现后以可控时钟、固定随机种子和模拟播放回执重放。F 表示实际起播的画面数，V 表示实际起声次数。

| 输入 | 期望 |
| --- | --- |
| 边界用例模拟血量 20%、19%、15%，随后死亡 | 20% 无警报；低血 F≤1、V≤1。死亡立即取消低血，死亡 F=1。 |
| 拖动 7 px，期间低血，随后死亡，松开又收到旧 onended | 保持跟手到松开。若已播过低血音不再播。释放后仅显示当前死亡反应，追加点击 F=0，旧片回调无效。 |
| 拖动中 19% 已口播，松手后分别得到同场 18%、20%、无新读数 | 仅 18% 补 A002 一次。其余两种均无低血画面，三种均无追加口播。 |
| 仍在同一点击回应中，2 秒内轻点六次；另测正好 6 px | 只启动一段回应。正好 6 px 属于点击，超过 6 px 且释放后不追加点击。 |
| 同秒升级、拾取四次，10 秒后稳定脱战；另测连续 30 秒无法脱战 | 前者普通反馈仅升级一次，拾取 V=0。后者过期无补演。 |
| 同一死亡过程已说安慰，4 秒后复活 | 复活可行礼，合计情绪 V≤1。已复活后到达的安慰被取消。 |
| 安全区查询角色资料，两次查询分别在 1.9 秒与 2.1 秒给出结果，第二次换轮 | 快路径无等待片；慢路径至多一段等待片，已核实结果一到即显示，旧轮不可再读。 |
| 目标 10000 铜，分别输入 0、1、1500、4000、7500、10000；另测目标零、换角缺快照 | 依次 A070、A069、A068、A067、A066、A065。目标无效与余额未知均没有档位动画。 |
| 首领仅消失；另测已核实首领获胜与升级同刻 | 前者首领 F=0、V=0；后者满足全部门槛时最多一次庆祝，无升级语句误配。 |
| 讲故事中说「让我静静」；安全待机时钟随后到点 | 已发声音停止，后续段取消，不说告别。可安静变换姿态，主动话题不会重开。 |
| 战斗中点「蓝鲸现世」；12 秒仍不可播。安全区开启喂饭但 20 秒无操作 | 分别给点播等待结束提示和无声退出小游戏；事后均无延迟补演。 |
| 安全久候达 90 秒；另测暂停 90 秒、睡眠中进入战斗、节庆节目正在播时开战 | 合格待机换安静替补。暂停不插片；进战退出睡眠或收起节目，立即处理有效危急。 |
| 当前片损坏或旧轮预载刚就绪时切角色 | 失败片在本会话跳过，状态可继续前进，已批准新轮文本不被播放器阻塞；旧预载不会上屏。 |

## 用 Node 复核三条核心规则

[参考实现](interaction-policy.mjs) 只负责画面仲裁、低血声音与字幕、钱袋分档。三个函数读取索引和传入的状态，没有 I/O 或跨调用副作用。以下示例可在本目录用 `node --input-type=module` 执行。

```js
import { readFileSync } from 'node:fs'
import { chooseVisual, lowHealthDelivery, walletAction } from './interaction-policy.mjs'
const index = JSON.parse(readFileSync('./interaction-animation-index.json', 'utf8'))
const state = { now: 5000, sessionId: 's', characterId: 'p', combatId: 'c',
  alive: true, inCombat: true, online: true, dragging: true,
  atBoundary: false, allowAlertAudio: true, allowAlertCaption: true }
const hit = { id: 'A002', origin: 'game', event: 'low_health', requestId: 's:low-1', eligible: true,
  observedAt: 3600, receivedAt: 4000, expiresAt: 13600,
  sessionId: 's', characterId: 'p', combatId: 'c', healthPercent: 19 }
chooseVisual(index, state, [hit])        // null，拖动占画面
const delivery = lowHealthDelivery(index, state, hit)  // audio=true，audioDisposition='reserved'
const next = { ...state, now: 5100, dragging: false, lastDragReleaseAt: 5050,
  latestHealth: { verified: true, sessionId: 's', characterId: 'p', combatId: 'c', at: 5080, percent: 18 },
  lowHealthLedger: {
  sessionId: 's', characterId: 'p', combatId: 'c', audioDisposition: delivery.audioDisposition,
  captionDelivered: delivery.caption } }
chooseVisual(index, next, [hit])?.id     // A002，仍未交付画面
lowHealthDelivery(index, next, hit).audio // false，已占用这次语音机会
walletAction(index, { requested: true, verified: true, characterId: 'p', activeCharacterId: 'p',
  balanceCopper: 7500, targetCopper: 10000 })          // A066
```

**候选如何归一化。** 宿主在各入口生成 `origin` 和 `event`，复核事实、允许的角色、战斗环境、玩家许可和频控后设置 `eligible`。这些字段来自可信适配器。候选可以省略主 `route`，旁路须明确填写。候选携带自填的 `priority` 或 `normalOrderKey` 一律丢弃；主次优先级都由索引导出。

| 已验证输入 | origin、event 与路由 |
| --- | --- |
| 主游戏信号 | origin 为 game，event 必须等于该行动的 bridge_event。A002 接 low_health，A007 接 death。 |
| 直接点播 / 第二菜单入口 | origin 为 menu、event 为 menu_confirmed；绑定目标行动的主菜单路由或准确的 secondary_route。必须有有限的 expiresAt，且从选择起未满 12 秒。 |
| 其他主用途 | origin 默认取该行 entry，event 取该行原 route。主动话题 A071/A072 的 origin 为 approved_proactive。A073 普通回复走 interaction；仅 approved_proactive + approved_reply_first_segment 可继承主动优先级。 |
| 两项新增联动 | 同一 action id、cross_routes.key、origin、event 须全匹配。A006 的胜利事件是独立的 boss_defeated，沿用升级的排序位置；缺少独立证据时适配器不得生成该事件。A073 故事首段使用 consented_story_segment_ready，须先核验剧情和授权。 |

**时间与收据。** 时间单位为毫秒。适配器先将可信的源时间映射到当前单调时钟，记录 `observedAt ≤ receivedAt ≤ now`。桥接源时间无法可靠换算的过期敏感游戏提示应丢弃。低血的 10 秒和普通游戏的 30 秒从 observedAt 起算，转发和重发不得刷新。桌面动作的 observedAt 为手势或状态产生时刻。只限状态退出的候选可以显式传 `expiresAt: null`。safeSince 为确认安全的起点，新开舞台或自然片尾可设置 atBoundary。
