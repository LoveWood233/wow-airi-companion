# 动作交接、尾帧结算与语音

本规格应用于八职业共用的 96 项动作。A 编号、触发含义和各职业取片路径沿用[共有索引](eight-class-common-96.json)。八职业录像记录了旧规则的选片与素材覆盖；客户端接线按下述尾帧和限频规则实施。

## 现有影片在哪儿跳

用录像的动作时间索引，从 `34e62b6` 的每段原始 MP4 解码首帧和末帧，再按实际播放次序配对。每个职业 96 段，产生 95 个接缝。760 对相邻端帧中，逐像素相同的有 0 对。H.264 压缩也会造成像素差，具体是否跳变要看人物姿势、位置以及前后几帧的运动方向。两处明显例子见下表。

| 录像时刻 | 源片切换 | 切换前后的实际画面 |
| --- | --- | --- |
| 02:45.792 | 战士 A017「吃饭·碗饭」→ A015「侧身急躁跑」 | 前段最后三帧已正面站稳，下一帧直接变为侧身跑姿，盾牌和重心一起移位。 |
| 10:12.750 | 牧师 A077「睡觉-循环」→ A078「睡觉-起来」 | 循环段末尾人物已经站起，起床段却从闭眼坐睡开始。按当前素材接片会出现一次倒退。 |

这些数据说明同职业动作没有统一的像素端点。抽样录像验证过的 768 个职业与动作组合仍然有效，动作命中和画面连续性是两项不同的验收结果。

## h3库如何生成端点

h3库的 v2.51 默认短片链路使用角色参考图、源动作视频和提示词做参考生视频。主链的 208 节点和两次采样没有绑定共用的起止姿势。右侧续接分支在保存的工作流中默认旁路。启用后，可以用上一段的末 5 帧引导下一段开头，再裁掉重复部分；24 fps 下这相当于约 0.21 秒的时序参考。它适合前后关系已经确定的长片。独立制作、可由玩家任意点播的动作还需要各自遵守同一套端点约定。[v2.51 工作流及节点 208、563、588、590](https://github.com/LoveWood233/ComfyUI-H3-Subject-Replace/blob/eb0920225a7c402d82586e20791fd69f931b1052/%E6%B5%B7%E8%9E%BAH3%2B%E4%BA%BA%E7%89%A9%E6%9B%BF%E6%8D%A2%E4%B8%93%E7%94%A8%E6%B5%81v2.51.json) · [作者对长片分支的说明](https://github.com/LoveWood233/ComfyUI-H3-Subject-Replace/blob/eb0920225a7c402d82586e20791fd69f931b1052/README.md#L37)

随库附带的 `MiniMaxH3ImageToVideoTail` 在启用 `apply_keyframes` 并传入两张图时，把它们分别编码为第 0 帧和最后一帧的采样条件。主工作流没有实例化这个节点。关键帧引导只约束生成；成品的姿态和像素仍须在导出 MP4 后复验。本次检查读取了发布的工作流和节点源码，未执行模型推理，现有 MP4 的生产参数也没有据此反推。[关键帧注入代码](https://github.com/LoveWood233/ComfyUI-H3-Subject-Replace/blob/eb0920225a7c402d82586e20791fd69f931b1052/ComfyUI-Installs/custom_nodes/ComfyUI-YCNodes-MiniMax-H3/py/minimax_i2v_tail.py#L181-L205)

### 制作约定

- 每个职业各自确定可复用的中立站姿。可任意互换的节目从该姿态自然起势，结束前回到同一姿态。统一画幅、朝向、脚底基线、人物大小和道具归位位置。保留动作前后几帧的收势与起势，单独贴一张标准帧容易把跳变挪到片内。
- 连续玩法按状态制作。以睡眠为例，A076 从站姿进入睡姿，A077 从睡姿开始并回到同一睡姿，A078 从该睡姿醒来到站姿。对进入、循环自接、退出三个接缝分别验收。当前 A077 的站立尾帧需要返工或重新选循环范围。
- 导出后检查真实解码端帧及端点附近的运动。每个职业先检查各段与对应标准姿势，再复看已知问题和实际允许的切换。脚底漂移、角色突然翻面、道具闪现和动作倒退应记录到具体片段及帧号。上述为制作与验收方案。

## 一次输入怎样生效

| 发生时刻 | 舞台 / 结算 | 语音 |
| --- | --- | --- |
| 输入到达 | 记录真实游戏状态和请求 ID。登记需要结算的互动，脚下拖窗可以立即跟手。画面仅产生一个待播候选，可以提前解码。 | 获准的不同语句各自入队。普通应答可在通道空闲时交付，独立于对应的画面是否被接纳。 |
| 当前动作播完尾帧 | 核对会话、播放代次和循环序号，以及最后一帧已经呈现完毕。释放待结算项，每个事件只结算一次；再核对候选时效、状态、额度和素材就绪情况。 | 依赖结算结果的语句在业务确认后才播；其他已就绪的语句按顺序继续。 |
| 下一动作首帧成功显示 | 将这次视觉触发计入当前固定窗口。一镜八格比较时，先结束的区域保持本轮尾姿，待八个格子的真实尾帧都结束，再一起呈现下一组首帧；一次共同触发只计一次。 | 动画未获额度、缺片、被更新候选替换或解码失败，均不撤销获准的独立语音。 |

危急状态可以立刻更新，危急语音也可以独立送出；对应动作仍等当前片尾。玩家要求安静或静音应立即生效。业务成功文案等待结算确认，失败时由业务层交付与真实结果相符的回复。重传同一事件或同一语音段需要去重。用户发起的不同语音互动不可因为命中同一个动作而被合并。

**固定窗口。** 从会话启动的单调时钟起点划分互不重叠的窗口。当前可运行的参考值为每 60 秒最多启动 2 次互动动画，参数可调整。初始待机不占额度，无请求时也不凑次数。窗口内仅保留一个合格的待播候选，优先级相同取最新。窗口结束或名额用完时丢弃未生效的画面候选；结算和语音保留。预加载、重复或失效回调、触发失败均不扣次数。固定窗口允许前一窗口末尾和后一窗口开头分别用额度，当前片尾约束始终生效。

**真实尾帧。** 普通片须等最后一帧的显示时段结束。已到尾帧而下段尚未准备好，可保持尾姿。循环片按每一轮的尾帧回执结算，错过该次切换则等下一轮。仅收到解码完成、定时器到点、过期的 ended 消息或某个格子的预载完成，都不足以代替整次呈现确认。播放故障要单独上报，不能假造一次正常结算。
